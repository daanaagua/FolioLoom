# External framework workers — 2026-09-11

## Implementation

- `book run --worker external --worker-profile` loads a native executable/argv,
  opaque framework/model identity, planning limits, and timeout. It invokes a
  versioned UTF-8 JSON stdin/stdout protocol from an isolated temporary directory.
- Run metadata stores backend, profile ID, and a normalized profile digest, not
  raw command arguments. Cross-backend or changed-profile resumes fail before
  generation. Source/style/glossary/scheduler contracts remain unchanged.
- Output bounds, timeout, owned-process-tree cancellation, request/model identity,
  safe error classifications, and provider-derived usage are enforced. Failed
  model-output turns retain available usage; absent or invalid usage remains
  incomplete. External code is trusted operator code, not an OS sandbox.
- The skill no longer requires a Codex host or Codex authentication for core or
  external operations. The dedicated Codex path and file-batching policy remain
  unchanged. OpenCode and Claude Code headless bridges use existing framework
  configuration; the same protocol supports custom CLI/SDK bridges.
- OpenCode visible output excludes reasoning in its session counters, so the
  bridge combines them into FolioLoom's inclusive output counter. Cache counts
  remain disjoint. Monetary cost is unpriced, not asserted to be zero billing.

## Verification

- Test-first checks covered CLI option exclusivity, profile capability validation,
  identity changes, real UTF-8 child-process I/O, tool output, missing usage,
  output bounds, timeout/cancellation, and failure-usage privacy.
- Core suite: 1018 passed, zero failures, one environment-dependent skip.
- Skill/bridge suite: nine passed. Core and desktop TypeScript checks passed.
  Skill frontmatter/reference validation passed for repository and installed copies.
- Live bridge: OpenCode 1.18.9 invoked configured `deepseek/deepseek-v4-flash`.
  A synthetic 117-word, two-paragraph English source imported into one window;
  the book run completed in 17.272 seconds with two model calls. One non-blocking
  model note described preserved paragraph layout; no recovery or failed window.
- Audit reported complete coverage, converged knowledge, and `strictExportable`.
  Strict export and export verification passed. Explicit same-run resume processed
  zero windows and made no new calls. Changing profile/model was rejected before
  the deliberately invalid replacement executable could start.
- Claude's protocol mapping and launch restrictions were tested offline; live
  end-to-end evidence above applies to OpenCode. Other frameworks require their
  own compatible bridge and bounded capability check. No full-book/100K quality
  or throughput conclusion follows from this sample.
