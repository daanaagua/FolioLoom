# 2026-10-09

## Scoped TLS compatibility and explicit transport recovery

- Native provider runtimes support an explicit classical-group compatibility mode
  for proxy routes incompatible with hybrid TLS key shares. X25519/P-256/P-384 are
  scoped to selected provider requests; TLS 1.3, certificate and hostname validation
  remain enabled. Global TLS defaults and unrelated concurrent requests are unchanged.
  The existing Undici 7.30.0 dependency is pinned as a production dependency.
- Direct startup now performs the same fresh read-only preflight as supervised
  startup before creating its store, acquiring a run lease or reserving tokens.
- The direct-recovery status/release CLI exposes durable, window-specific recovery
  authorization. Releases require the run identity, last request, reason and bounded
  additional attempts. Pure transport exhaustion is eligible; semantic/structural
  results, missing response evidence, stale requests and active writer leases are not.
  Duplicate requests are idempotent and ordinary restart preserves remaining credit.
  No release exceeds eight lifetime attempts, expands the token envelope or clears
  unknown accounting. This is not the proposed cross-phase provider coordinator.
- Regression tests first reproduced hybrid ClientHello group selection, direct
  preflight reservation ordering and exhausted recovery. Tests inspect local TLS
  handshake groups/version offers, concurrent scope isolation, failed preflight
  filesystem effects, durable credit, duplicate/stale releases, semantic rejection
  and active-lease protection. Historical unknown usage remains a strict-export block.
- Validation: 78 focused tests and 1,414 full core tests passed, with one Windows
  environment skip; core/desktop type checks, desktop build and artifact check passed.
  Read-only real-route probes with scoped compatibility negotiated TLS 1.3/X25519
  successfully three times. Documentation and portable skill instructions match.

## Typed direct naming and deterministic waves

- New protocol 3 returns typed entity names or sense-bearing contextual terms with
  exact paragraph evidence alongside translation. The parser verifies source quotes
  and aligned target occurrences; ordinary, uncertain or unsupported entries are
  discarded without additional model work. Semantic classification remains model-owned.
- Person/place/organization/work names are book-scoped constraints; terms are soft
  context preferences. Comparison tolerates paired outer title/quotation marks and
  explicitly attested English possessives without rewriting prose or merging forms.
- Persistent waves freeze membership and base names, collect all drafts, then merge
  in source order. All declared hard conflicts in one window share a frozen repair
  plan and the original attempt budget. Failed peers release waiters; saved drafts,
  plans and checkpoints survive restart with lower execution concurrency.
- Protocols 1/2 retain original identities and prompts. Protocol-2 recovery scans
  saved responses for the same exact window, paragraph IDs and seed mode against
  current constraints, even across naming-context hashes. Replay records provenance
  without an extra request, settlement or renewed allowance.
- Test-first recovery regression reproduced an exhausted window whose final saved
  response was valid while earlier candidates conflicted. The fix reuses only the
  valid response. Existing conflict exhaustion and protocol-1 compatibility pass.
- Validation: 1,407 core tests passed, one Windows environment skip; 30 direct tests,
  core/desktop type checks, five run-interface tests and desktop production build
  with artifact verification passed. Translation skill instructions are synchronized.
- Native protocol-3 smoke covered two sequential windows, process restart and a
  two-window concurrent wave: four responses, 5,188 real tokens, no retries or unknown
  usage; typed entity/context-term memory and strict export verification passed.
  The smoke does not establish full-book semantic quality or throughput.

  protocol. Source-only window planning, bounded concordance and one frozen naming
  table replace normal-path model planning, anchoring, semantic review and closure.
- New native CLI and desktop tasks select direct generation. Explicit supervised
  workflows and existing runs keep their prior behavior; external workers retain
  their adapters. The public core API exposes an explicit workflow selector.

  Persisted paragraph splits retain both completed groups and seed conventions.

## Durable provider recovery design

- Added a proposed architecture covering durable operation/attempt identity,
  retry due times, provider circuits, explicit recovery epochs, fencing, and
  cancellation. Existing run identities and production recovery policy are unchanged.
- Located complete-usage retry gates in recovery, supervision and translation;
  final quality restart currently blocks the interrupted item, and supervisor
  transport attempts consume semantic checkpoint credit. Crash reconciliation
  also needs distinct observed-usage and conservative-debit fields.
- The design preserves actual usage evidence and strict export accounting,
  prohibits hidden model/provider substitution and unbounded retries, and defines
  deterministic fault injection across all provider phases and persistence boundaries.
- Current recovery, supervision, token-ledger and ledger-store tests: 79 passed,
  zero failures. These validate the existing behavior, not the proposed coordinator.

## Source-grounded lowercase inflection discovery

- English discovery recognizes bounded hyphenated modifiers, plural group phrases,
  quantifiers with stronger noun evidence, and contracted auxiliaries. Three-letter
  forms use the same contextual checks and ordinary-word exclusions.
- Attested regular inflections contribute discovery evidence without stemming the
  source, merging identities, inventing aliases or inflating exact-form counts.
  Established forms can supply read-only support without being rediscovered.
- One existing lowercase slot protects a low-frequency attested inflection, with
  explicit group evidence prioritized over incidental inflections. The four-slot
  lowercase and sixteen-slot overall limits are unchanged.
- Both native and framed lexical transports retain a source-grounded singleton
  technical sense as soft memory when a repeated related form supplies evidence.
  Own-form quotes remain mandatory; related forms do not satisfy the independent
  concept threshold. Each exact form retains its own preferred sense and audit row.
- Test-first fixtures reproduced missing group nouns, regular inflections,
  established-form support, quota crowding and dropped singleton preference data.
  A broader run exposed quantifier-only boilerplate discovery; a focused regression
  now requires stronger noun evidence rather than adding a word-specific exception.
- SQLite integration verifies separate durable senses, all four source occurrences,
  unlocked policies, close/reopen projection and resume without another model call.
- Verification: 1371 core tests passed, one Windows environment skip, zero failures;
  core/desktop type checks, production desktop build and build-artifact test passed.
- Storage schema, provider effort, request/review limits and existing translations
  remain unchanged. Unmarked isolated lowercase words and irregular inflections are
  outside the guaranteed coverage of this bounded syntactic discovery channel.
