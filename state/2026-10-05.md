# 2026-10-05 — review lifecycle findings

## Context planning performance

- Admission variants share a bounded 128-input LRU planner cache per planning
  pass. Keys contain all decision fields and exclude evidence payloads; results
  are defensively copied. Changed budgets, costs, requirements or identities miss
  the cache. Key storage is bounded to 16 MiB, with no process-wide evidence cache.
- Independent candidate frontiers retain exact token, entry, byte and utility
  dominance using compressed two-dimensional prefix maxima. Dependency-bearing
  plans keep their original path. Small frontiers and non-finite accumulated
  utilities retain pairwise pruning; exact identity ties are resolved only for
  surviving resource tuples in the indexed path.
- A 137-candidate synthetic varied-cost fixture preserves all three reference
  profiles, including exact IDs, costs, utility and coverage. Pairwise baseline
  times were 17.54/17.66/17.67 seconds; indexed cold solves measured approximately
  13.2–13.9 seconds. Repeated equivalent inputs measured 0.2–0.3 milliseconds.
  These are local planner measurements, not translation-throughput measurements.
- `npm run benchmark:context` checks the exact reference profiles and reports
  cold/repeated timings and solver call count without any provider requests.
- Differential checks matched 600 seeded inputs and their reversed permutations
  against the original solver. Automated coverage includes 250 seeded frontier
  comparisons, cache invalidation, output mutation isolation, LRU eviction and
  invalid-input rejection. Full regression: 1186 passed, one Windows environment
  skip, zero failures; core/desktop type checks and desktop build passed.
- Cold planning still scales with the number of non-dominated resource states;
  cache reuse removes repeated solves, not the first solve for a new input.

### Cross-bucket frontier reduction

- Independent evidence now prunes dominated states across token buckets with
  identical coverage. A cheaper state using no more entries/bytes and providing
  no less utility can replace the dominated state for every remaining independent
  choice. Exact budgets, required coverage, mandatory closure and all resource
  tradeoffs remain enforced; no evidence-count or budget limits are reduced.
- Overflow-sized utility inputs and distinct IDs that collate equally retain
  the original bucket-local path. Dependency-bearing planning is unchanged.
- The same 137-candidate fixture generates 1,370,168 candidate states instead
  of 15,731,246; peak retained states fall from 204,386 to 15,905. All three
  profiles still match the original pairwise-solver golden result exactly.
- The ordinary offline benchmark measures about 1.10 seconds uncached, versus
  the first indexed version's 13.21 seconds. Instrumented alternating-order
  measurements were 16.15/19.56 seconds before and 1.60/1.58 seconds after.
  Repeated equivalent cached requests remain below one millisecond. These are
  synthetic local planner measurements, not whole-book execution timings.
- 1,800 seeded inputs and their shuffled permutations match the original solver
  in 3,600 exact comparisons, including fractional/negative/extreme utilities,
  collating-equal IDs, dependencies, zero costs and infeasible resource budgets.
  The heterogeneous golden regression also enforces a five-second planning bound;
  it failed at 14.28 seconds before this change and passed at 1.10 seconds after.
- Regression: 1,188 passed, one Windows environment skip, zero failures;
  core/desktop type checks and the production desktop build passed.

## Review lifecycle

- Typed knowledge revalidation creates a fresh dependency-scoped plan but uses
  the ordinary window review counter. Two earlier reviews plus one revalidation
  review can exhaust the cap before a repaired candidate receives its follow-up.
- Explicit pauses remain durable; resume does not automatically replenish credits.
  The revalidation executor also lacks the repaired-candidate admission callback
  available in the ordinary translation path.
- Provisional observations currently recognize proposed or previously known target
  forms. An unfamiliar actual rendering can remain unknown despite repeated source
  occurrences. Source-only candidate memory is not a complete alignment mechanism.
- New sibling evidence can cause another whole-window review of an unchanged
  candidate. Short disposition notes do not bound internal model reasoning or its
  replay in later tool turns.

## Implemented lifecycle and evidence controls

- Quality mode uses only the selected runtime in desktop, CLI and active planning.
  Explicit fast mode retains lower-effort candidates; the default remains high.
- Same-call optional surface receipts use host-owned occurrence IDs, paragraph
  positions and observed target text. Partial receipt coverage remains unknown;
  unrelated target paragraphs and stale quote relocation cannot establish a mapping.
  Observations remain provisional and scoped; ordinary repeated words are not
  collected solely because of frequency.
- Full review can seed durable paragraph-delta review. Deltas include changed
  paragraphs, neighbors, affected terminology and all still-open issue spans.
  Structural uncertainty or an oversized journal base falls back to full review.
  Identical candidate/dependency/evidence combinations reuse their receipts.
- Native controller decisions have two model turns, with compact source-only
  concordances and one optional evidence-query round. Active tool-session provider
  reasoning state remains intact. Prompts separate source facts from rendering
  conventions and reject stylistic preference as evidence of semantic error.
- Dependency-scoped review epochs each allow three attempts; a twelve-attempt
  lifetime ceiling prevents unbounded refresh. Repair checks follow-up review
  capacity before dispatch, including typed revalidation and final-quality paths.
- The generation-checked derived surface quarantine appends superseding revisions
  and snapshots. It rejects active-window edits, preserves original history and is
  idempotent. It does not release pauses or change translations, quality or usage.
- Snapshot audit consumes explicit consecutive superseding revisions when a subject
  leaves the projectable set. Missing entries without such a durable revision still
  fail history validation; removed records are not silently ignored.
- Validation: 1132 tests passed, one Windows symlink environment skip, zero failures;
  core and desktop type checks and production desktop build passed. Regression
  coverage includes per-occurrence drift, missing/forged receipts, delta cache reuse,
  open-issue retention, dependency epochs, pre-repair admission and quarantine.

## Structured decisions and paragraph receipt transport

- Supervisor protocol 3 selects JSON-object terminal decisions for DeepSeek while
  retaining bounded source queries. Schema, issued evidence, scope and issue closure
  checks remain mandatory; native-tool decisions remain available for other providers.
- DeepSeek uses max_tokens. The reasoning-inclusive supervisor ceiling is 32768,
  bounded by model capacity and shared with admission accounting. Other providers
  retain their existing ceiling. Configured reasoning effort is unchanged.
- Shared semantic paragraph spans preserve original UTF-16 and scalar coordinates,
  ignore whitespace-only trailing segments and recognize certified scene separators.
  True paragraph merges still fall back to full review.
- Fragment and single-paragraph requests include only owned surface occurrences.
  Receipts use local target paragraph positions without changing global identities;
  assembly, refinement and checkpoints preserve grounded observations.
- Per-response accounting distinguishes provider responses from explicit local
  turn-limit sentinels. Research-run merging retains the response lineage. A positive
  aggregate cannot make a missing response complete or authorize another retry.
- Regression validation: 1142 core tests passed, one Windows environment skip,
  zero failures. Core/desktop type checks and production desktop build passed.

- Wire focus lengths remain bounded; canonical spans can include intervening markers.
  Revalidation of journal decisions preserves those spans. Actual text changes,
  unknown markup, ambiguous visible matches and unissued references remain invalid.
- Two retained response fixtures replayed successfully; counterfactual text and

## Host-owned EPUB repair structure and bounded quality rework

- Structurally valid EPUB semantic candidates use text-slot patches instead of whole
  replacement blocks. Candidate hashes and exact prior text bind each edit; neighboring
  paragraphs are read-only, fixed breaks stay immutable and marker injection is rejected.
- Patch validation precedes atomic application. Tests cover multiple slots, CRLF, astral
  characters, stale bases, duplicate/out-of-scope slots and preserved structural markers.
- Quality rework requests append a new pending round with the prior record identity,
  protocol, idempotency key and reason. Active run leases, stale candidates and conflicting
  request reuse are rejected. Original history remains intact; explicit rounds are bounded
  to two and the twelve-review lifetime window cap is unchanged.
- Review and repair checkpoints are scoped to the new round while accounting remains in
  the original run. Integration coverage proves successful closure, strict export readiness,
  no retranslation of completed windows and no calls on a subsequent ordinary resume.
- Validation: 1152 core tests passed, one Windows environment skip, zero failures;
  core/desktop type checks and production desktop build passed.
- Fixed-disposition checks now bind the original host candidate and distinguish
  issue-local edits from unrelated changes. An inserted negation can leave the old
  phrase as a substring; bounded exact edit alignment handles this without treating
  unchanged evidence as fixed. The same check protects the storage commit boundary.
- Final-review recovery scopes include their durable quality-round identity. Original
  recovery records and the global/lifetime caps remain intact across explicit rework.
- Extended validation: 1154 core tests passed, one Windows environment skip, zero
  failures; core/desktop type checks and production desktop build passed.

## Ordered EPUB repair values

- Semantic EPUB repairs return one JSON string/null array in the exact issued slot
  order. Null preserves a slot. The host supplies candidate hash, slot identity,
  expected text and empty notes before the existing atomic patch validator.
- The terminal response path exposes no tools and admits one model turn. Missing or
  extra positions, wrappers, invalid types, marker/separator injection, no-op results
  and stale candidates are rejected without partial edits. Rejected responses keep
  provider usage and evidence. Ordinary block repair and historical records retain
  their existing contracts.

- Focus conversion now retains grounded source/target quotation scopes. A repeated

  Regression covers two intended paragraphs and an unchanged outside occurrence.
  Extended validation: 1158 core tests passed, one environment skip; core/desktop
  type checks and production desktop build passed.
