# DeepNovel-Translator parallel_v4 第一版规格

## 1. 目标

第一版在不修改 `serial_v3` 项目数据的前提下，增加可回滚的影子流程：

```text
legacy project → migrate-v4 → scan-v4 → reconcile-v4
               → translate-v4 → compare-v4/validate-v4 → export-v4
```

第一版只完整支持英语原文。核心目标是建立语境词汇知识、并行翻译和可验证提交机制；不解释象征、叙述陷阱或文学主题。

## 2. 第一版边界

第一版必须实现：

- SQLite 证据库、知识版本、规则作用域和反向依赖；
- 原项目的非破坏性迁移；
- 按文本块并行扫描翻译必需信息；
- 严格 JSON Schema 校验，解析失败不得降级接受；
- 基于原词的保守归并，不确定别名不得强制合并；
- 只检索当前文本命中的概念和语境规则；
- 小岛内部串行、小岛之间并行；
- 同一批次读取同一个知识版本，协调器按固定顺序单写入；
- 动态并行度、有限重试、审计日志和断点恢复；
- 复用两层翻译器，但影子译文只写 SQLite；
- 严格导出和允许警告导出；
- TXT、EPUB 和独立质量报告。
- `interactive` 模式的CLI人工队列查看、接受和拒绝；人工接受项必须锁定并触发受影响译文复验。

第一版不实现：

- 完整故事时间线、揭示时间表和多重文学解释；
- 自动典故注释；
- 多语言形态分析器；
- 自动将书内规则提升为全局规则；
- 完整 Web 裁决界面。第一版只建立可持久化人工队列和 CLI 状态，第二版接入 Web UI。

## 3. 数据原则

### 3.1 证据不可变，结论可修订

`evidence` 和原文块只追加。`concepts`、`rendering_rules` 和 `usage_decisions` 带知识版本。人工锁定项不得被模型覆盖。

### 3.2 规则作用域

作用域固定为：`language`、`genre`、`book`、`thread`、`speaker`、`occurrence`。第一版自动生成项只能写入 `book` 或 `occurrence`。

### 3.3 保守归并

第一版只对大小写、所有格等确定性英语词形进行归一化。别名、身份和性别推断保留为候选证据，不自动合并。

### 3.4 上下文硬预算

当前原文、命中的硬规则和最低限度相邻上下文之和超过预算时，任务进入 `incomplete_requires_human`。不得自动摘要、删除规则或伪装完成。

## 4. 并发协议

1. 调度器选择若干连续小岛，每个小岛默认 3 个块。
2. 同一批次的所有小岛读取相同 `knowledge_version`。
3. 每个小岛内部按原文顺序串行翻译。
4. 工作线程只返回译文、证据和变更建议，不写 SQLite。
5. 协调器等待批次结束，按章节和块序提交。
6. 提交知识建议后产生新版本；受影响旧译文先标记 `needs_revalidate`。
7. 连续成功时逐步提高并行度；API过载或结构错误时降低并行度。

## 5. 状态

文本块状态至少包括：

```text
pending
scanned
ready
translating
completed
completed_with_warnings
needs_revalidate
incomplete_requires_human
failed_retryable
failed_terminal
```

## 6. 模型角色

配置支持 `scan`、`reconcile`、`draft`、`polish` 和 `verify` 独立模型。第一版允许它们都回退到 `draft` 模型。

## 7. 审计

每次调用记录运行ID、用途、模型、提示词版本、知识版本、请求、原始响应、解析结果、耗时、重试和接受状态。密钥不得进入数据库或日志。

## 8. 验收

- 旧 JSON 项目和旧导出结果不被修改；
- 迁移可重复执行且不产生重复块；
- 扫描结果必须通过严格结构校验；
- 并行工作线程不能直接写 SQLite；
- 批次提交顺序与模型返回顺序无关；
- 中断后从最后一笔事务恢复；
- 上下文溢出时不调用模型；
- 影子导出不得混入旧译文；
- 第一版自动化测试全部通过。

## 9. 第二版候选

第二版在第一版通过后再实现揭示边界、时间约束、假说并存、高影响双重核验、局部段落修复、Web 人工裁决和可选注释模块。
