# FolioLoom v1.12.0

Windows x64 portable EXE and ZIP. This release consolidates the changes since
v1.8.1, including direct translation, typed naming memory and bounded recovery.

## 中文摘要

- 新建原生 CLI 和桌面整本任务默认直接翻译，不自动追加模型规划、词义研究、
  语义审校或反复结案调用；旧任务和显式监督流程保持原有行为。
- 直译协议 3 随正文记录有原段证据的类型化译名。稳定实体形成硬约束，专用术语
  保留为语境偏好，普通词和不确定条目不入表。固定并发轮次按原文顺序合并译名，
  已申报的冲突按冻结方案在原有额度内修复。
- 响应先落盘，再提交窗口；中断后可复用符合条件的响应，已完成的并发窗口不会
  因其他请求失败而丢失。原有协议保留运行身份、响应证据和真实用量。
- 连接预检在建库和预留调用额度之前执行。显式 TLS 兼容模式限定在所选服务请求，
  保留 TLS 1.3 和证书校验；纯传输失败窗口可显式释放有限恢复额度，累计最多八次。
- 保留精确段落覆盖、顺序、Unicode 和 EPUB 位置校验，以及完整交付和严格交付。
  监督流程另含按窗口术语依赖复用缓存、源文规划和有界并发改进。
- 更新 source-map-js 至 1.2.2，修复高危依赖问题；高危依赖审计门禁通过。

## Compatibility and limits

- Storage remains schema v5. Existing runs keep their workflow and protocol identity;
  changing workflow or protocol requires a new run. Back up projects before upgrading.
- Direct translation does not perform exhaustive semantic review. Undeclared names,
  mistaken classifications, sentence-level omissions and distant references can escape
  local checks. Optional naming entries without required evidence are discarded;
  later conventions do not automatically rewrite earlier translations.
- Unknown provider usage remains visible and blocks strict accounting acceptance.
  Restart and duplicate recovery releases do not replenish exhausted allowances or
  erase historical usage. Standard delivery does not imply strict acceptance.
- Windows binaries remain unsigned. The legacy ExcelJS/UUID dependency chain retains
  two moderate audit findings; the high-severity dependency gate is unchanged.

## Downloads

- `FolioLoom-portable-win-x64.exe`: single-file portable application.
- `FolioLoom-portable-win-x64.zip`: extract the entire archive, then run `FolioLoom.exe`.
- `SHA256SUMS.txt`: SHA-256 checksums for both downloads.
