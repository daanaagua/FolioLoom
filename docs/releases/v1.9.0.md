# FolioLoom v1.9.0

## 中文

- 新运行默认交付完整译本及疑点清单；严格交付仍可选。语义疑点经过有界修复和书末复核，结构、原文身份、锁定术语和真实用量仍是硬门禁。
- 暂态模型故障与导出文件占用可有界恢复，次数与停止状态跨重启保留。旧版不合格候选可隔离并回退到通过验证的候选，历史记录和原有修复额度不被清空。
- 监督缓存按实际窗口术语依赖判定。无关知识变化不触发重新规划；相关约束变动仍需新审校。批次计划保存逐窗依赖，避免相邻窗口的变化使已有审校失效。
- 不同窗口的监督请求可并行，同一窗口和重叠计划保持有序，最多三路且不超过运行并发设置。设为单路时仍串行，不自动提高模型并发或改变推理档位。
- 翻译请求仅携带相关、已建模术语及其别名关联，同时保留适用的锁定项、旧格式记录和上下文引用项。持久化知识、术语校验和用量核算不裁剪；准入与运行使用同一个请求构造器。
- 修正累计预算与峰值占用混用、监督终结动作无预留、坏修复过早写入检查点等边界问题。EPUB 保留跨块原文空白，并按 EPUB2 NCX / EPUB3 nav 分别校验。

已有运行继续使用原有后端、监督与交付策略；首次采用窗口级依赖时，旧格式缓存可能需要重新生成。显式暂停不会自动释放。模型耗时受服务响应、原文难度和修复量影响，吞吐优化不承诺固定完成时长，也不减少原策略要求的审校覆盖。

## English

- New runs default to a complete translation with an explicit quality-issue report. Strict delivery remains available; source identity, structure, locked terminology and usage accounting remain hard gates.
- Transient provider and export I/O failures have durable, bounded recovery. Invalid legacy candidates can be quarantined and replaced by a validated earlier candidate without erasing history or replenishing repair credit.
- Supervision cache identities follow window-relevant terminology. Batch plans retain per-window dependencies; unrelated changes no longer invalidate an accepted sibling review.
- Independent supervision operations may overlap, while overlapping scopes retain FIFO order. Capacity is capped at three and at the configured run concurrency. Single-concurrency runs remain serial, and reasoning settings are unchanged.
- Translation wire payloads omit unrelated modeled terms while retaining applicable locks, legacy records, context references and entity/alias closure. Full local terminology and validation remain intact, and admission uses the same payload builder as execution.
- Boundary fixes separate cumulative token cost from peak occupancy, reserve supervisor completion resources, validate repairs before checkpointing, preserve source whitespace across EPUB block partitions, and validate EPUB2 NCX separately from EPUB3 navigation.

Existing runs retain backend, supervision and delivery identity. Legacy caches may be regenerated on first use of scoped dependencies; explicit pauses are not automatically released. Throughput depends on provider latency, source complexity and repair volume; no fixed completion time or reduced review coverage is implied.
