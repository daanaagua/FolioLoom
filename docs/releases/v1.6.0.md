# FolioLoom v1.6.0

FolioLoom v1.6.0 adds an optional Codex CLI execution backend and a repository-scoped Codex
skill for auditable long-form translation without a separate model API key. The existing
provider API and desktop workflows remain available and retain their previous run identities.

## Codex worker

- `book run --worker codex --codex-model MODEL_ID` launches a fresh isolated `codex exec`
  subprocess for each physical model request and reuses the user's local Codex login.
- Source text is sent through UTF-8 stdin rather than process arguments. The subprocess runs
  in a temporary directory with a read-only sandbox, structured output, ephemeral sessions,
  ignored user rules/configuration, and no project database path.
- Codex execution is persisted as `executionBackend: codex-exec`; provider and Codex runs
  cannot be resumed through the wrong backend or under a different model/policy identity.
- CLI authentication, quota, network, invalid output, cancellation, and incomplete usage are
  explicit boundaries. Missing usage is never synthesized and still blocks strict export.

## File-translation efficiency and recovery

- The `codex-file-v1` policy can pack two adjacent logical windows into one bounded physical
  request while retaining independent validation and durable commits.
- Stable serial work can prepare two physical request horizons from one lexical-anchor
  snapshot; retries and unstable knowledge states automatically return to one horizon.
- Paragraph-heavy blocks are attempted whole before the existing bounded paragraph-fragment
  recovery topology, reducing unnecessary calls without weakening shape validation.
- Terminal typed-protocol tails can be repaired into a new audited translation version.
- Paragraph-heavy DOCX extraction now assembles text in linear time instead of repeatedly
  rebuilding the accumulated document.

## Repository-scoped skill

The new `.agents/skills/folioloom-translate` skill drives the safe file-first workflow:
environment doctor, native import, deterministic preflight, a two-window smoke, exact-run
resume, status inspection, audit, strict export, and export verification. Its portable
resolver supports explicit roots, `FOLIOLOOM_HOME`, and repository ancestors, including
paths with spaces and non-ASCII characters.

The skill contains no credentials, books, projects, databases, model output, or fixed user
paths. Codex authentication remains in the user's normal Codex installation and must never
be copied into the repository or release assets.

## Current boundary

The Codex backend is currently command-line/skill only, supports quality-mode sequential
execution, and requires `--max-concurrency 1`. It is not exposed in the Electron desktop UI.
This release does not claim a new Codex 100K throughput benchmark; the README's V4 Flash
figures remain historical provider-run measurements.
