# FolioLoom 1.5.0

本版本集中解决长篇翻译在模型输出退化、进程中断和知识重验证阶段可能出现的丢段、重复扣账、错误转人工以及无法严格导出问题。翻译质量门槛没有降低；恢复链路改为在同一套可审计预算与原子提交规则下逐级降解。

## 长段落与多段落恢复

- 正常整块翻译若出现漏段、异常缩短或结构坍缩，会按固定顺序降解为段落向量，再在必要时降解为单段叶子。
- 单段叶子只要求模型返回完整译文文本；窗口、块、段落、快照和执行身份全部由本地调用持有，避免模型误写路由元数据。
- 段落结果必须完整覆盖原文段落身份，缺失、重复、乱序、混用快照或上下文段落外泄都会失败关闭。
- 所有片段只在完整组装并通过整块校验后一次性提交，不会把半成品暴露为活动译文。

## 知识重验证统一执行链路

- 知识变更触发的 revalidation 不再直接调用模型，而是复用与普通窗口相同的 ExecutionWorker 恢复链路。
- revalidation 仍独立负责旧版本检查、相邻已提交译文边界校验和原子替换，不会被伪装成普通新窗口。
- 整块输出退化时可以在同一次外层 attempt 内恢复为段落执行；最终候选完整后才允许替换旧译文。
- exact source occurrence 即使合法省略 preferred/contextual receipt，也会建立干净 coverage binding；locked receipt 仍严格要求提交。

## Durable token ledger 与恢复安全

- 所有 provider 调用都经过 reserve → dispatch → settle 生命周期；已发车但 usage 未知的中断按保守上界结算，不再释放成零成本。
- repair、protocol switch、context split 和 paragraph fragment 使用跨进程唯一的 durable attempt ID；恢复后不会复用已终结的账本 ID。
- parent revalidation 与 secondary recovery 各自只结算自己拥有的 provider usage，避免重复扣账。
- 策略基线完整覆盖整块执行、段落恢复、一次单段 refinement 和最多三个 scoped repairs；顺序恢复预算不会被误当成并发 in-flight token。

## 调度与严格导出

- Active scheduler 在动态 context profile 不可行时保留已验证的 rich baseline variant，避免合法任务被误报为 `NO_LEGAL_PLAN`。
- resume baseline 按稳定 logical task 去重，不会因 physical request 重组扩大 token envelope。
- strict export 要求结构完整、知识收敛、coverage 完整、usage complete 且无 stale/warning-stale incident。
- 原始 provider assistant response 以压缩 sidecar 和哈希引用保存，便于区分模型坍缩、协议错误和 adapter 丢失；凭据、cookie 与 prompt 不进入证据。

## 下载与升级

- 推荐下载 `FolioLoom-portable-win-x64.zip`，完整解压后运行目录中的 `FolioLoom.exe`。
