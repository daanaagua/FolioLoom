# FolioLoom v1.13.0

Windows x64 portable EXE and ZIP. Binaries are unsigned. The optional semantic
review workflow is available through the CLI.

## Downloads

- `FolioLoom-portable-win-x64.exe`: single-file portable application.
- `FolioLoom-portable-win-x64.zip`: extract the entire archive, then run `FolioLoom.exe`.
- `SHA256SUMS.txt`: SHA-256 checksums for both downloads.

## Changes

Direct protocol 5 accepts source-attested naming corrections in the normal
translation response. Each concurrent wave reads a frozen versioned catalog;
the coordinator settles proposals before subsequent windows begin.

- Names accepted by protocol-3 wave plans survive repairs that omit unchanged
  entries, after validation against the final source/translation pair.
- Corrections include an expected revision, source evidence and target-position
  receipts. User-owned glossary entries are protected; conflicting or unsupported
  proposals remain visible through `book direct-naming status`.
- Precisely anchored name uses can be updated in peer drafts and prior translation
  versions. Local edits preserve provider responses and old translation versions.
- SQLite publishes the new catalog and historical local edits atomically. Saved
  wave plans support restart without repeating successful provider calls.
- Physical requests are planned from paragraph count, source length, markers and
  naming output. Compact semantic receipts use local IDs; the host derives exact
  positions only when unambiguous. Structured continuation references are filtered
  for each request instead of repeating the entire catalog.
- Validated fragments do not consume failure credits. A fixed token budget and
  call guard bound all generation and survive restart, including successful calls.
- Protocol-five token budgets can receive explicit per-window grants through
  `book direct-recovery extend-budget`. Grants retain the original ceiling and
  usage, reject stale boundaries, and apply only once per request ID. They do not
  renew failure credits or reconcile unknown usage.
- Native socket and connection failures retain sanitized transport codes through
  the SDK boundary. Recognized transport failures pause generation without
  exhausting the remaining credits through provider-busy retries.
- Old protocols retain their original prompts and run identities. Protocol-four
  revision events require a compatible reader. Storage schema remains v5.

Direct translation adds no automatic model review. The separate `book review`
commands provide a free scan, deterministic unflagged samples and explicitly
budgeted, read-only semantic comparisons. New source imports retain scope
certificates; excerpts can carry complete original-source range decisions through
`book scope` and `book import --original-manifest --scope-plan`.
See [source scope and review](../source-scope-and-review.md).

Structural/export acceptance and semantic
interpretation remain separate; a source quote cannot prove that a naming choice
is correct. Protocol 5 defaults to eight failed attempts, configurable up to sixteen;
protocols 1–4 retain their original total-attempt accounting.

## 中文

新增原文范围证据：分批导入可逐项记录原书中参与翻译、明确排除和计划重新生成的
内容，缺项、范围重叠、来源变化或所选文本不匹配会被拒绝。来源证据保留到数据库
及导出审计，旧运行身份不变。

新增独立的 `book review scan/run/status`：规则扫描不调用模型，可确定性抽查未报警
段落；模型复核须显式提供调用及 token 预算，要求原文和译文引用依据，重启不续杯。
疑点不会自动改写译文；结构验收与语义完整性仍分开表示。

直译协议 5 将译名更正提议与精简位置记录放在正常翻译响应中。并发窗口读取同一份
带版本的词表，协调器在轮次结束时统一处理提议，再向后续窗口发布新版本。

修复协议 3 中返修省略未变化词条导致已接受译名丢失的问题。人工词表受到保护；
冲突、过期或缺乏可靠位置的提议保留为可查询记录，不触发额外模型审校。
可确定的局部更名会保存新译文版本，原响应与旧版本保留。SQLite 原子发布词表
与历史局部修改，崩溃恢复复用已保存结果。旧运行继续使用原协议与身份。

请求按段落数、原文长度、结构标记和译名输出负担提前分组；历史参考译名按当前
原文筛选。模型用短编号声明语义对应，程序仅在无歧义时计算位置。成功片段不占
失败额度，但所有调用仍消耗固定总 token 预算，并受持久化调用数上限约束。
协议 5 可通过 `book direct-recovery extend-budget` 为指定窗口显式追加预算。
追加记录保留原始上限和历史用量，重复提交只生效一次，过期边界会被拒绝；
不会刷新失败额度或消除未知用量。
原生连接故障会保留脱敏的底层错误码；已识别的传输错误暂停生成，不再按服务繁忙
连续消耗剩余失败额度。
