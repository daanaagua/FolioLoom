# FolioLoom v1.7.1

A reliability and performance patch for live terminology control and long-running
translation sessions. Windows x64 portable EXE and ZIP remain the supported builds.

## Fixed

- Local terminology edits calculate non-overlapping spans against the original
  translation and apply them once. Newly inserted text is never replaced again.
  Intersecting matches, substrings of already allowed renderings, and overlaps
  with other recorded surfaces fall back to model revalidation.
- Strict export replays persisted local edits from original translations and
  receipts, including local-edit ancestors of the current version. Historical
  cascading corruption now raises `TERM_RETROFIT_INTEGRITY_INVALID`, even when
  old bindings claim to be clean. Audit is read-only; it does not rewrite history.
- One terminology rule can have multiple source forms without a false rule-ID
  conflict. Per-spelling, per-block overrides remain isolated. Incompatible
  metadata under a shared rule ID still fails closed.
- Every applicable rule in the highest-precedence tie group is checked, not just
  the first two. A conflicting third rule can no longer be silently ignored.
- A local run can recover a lease left by a confirmed dead process. An
  OS-released SQLite sidecar lock serializes competing reclaimers. Live owners,
  unknown/malformed records, permission failures, and hostname mismatches remain
  blocked; lock age alone is never grounds for deletion.

## Performance and maintenance

- Translation projection and durable rule-conflict checks compile a source-form
  index once per operation instead of repeatedly scanning/normalizing all rules.
- On one local synthetic comparison (8 blocks), 100 / 500 / 2,000 candidate terms
  took about 2 / 8 / 22 ms, versus 119 / 2,969 / 71,100 ms in v1.7.0. These are
  resolver-only samples, not end-to-end translation speed claims. A generous
  5-second regression budget covers the 2,000-term case.
- Updated the build-only `@xmldom/xmldom` dependency to 0.8.15. High/critical
  dependency audit gates pass. The two existing moderate `exceljs -> uuid`
  findings remain; no breaking dependency downgrade was forced.
- Root `STATE.md` is concise and current; the old July execution record is
  preserved under `state/` instead of presenting an obsolete release freeze.

- Desktop Node suite: 113 passed, 1 skipped, 0 failed; renderer: 67 passed.
- Core and desktop TypeScript checks, skill environment tests, and production

- Regression coverage includes real SQLite commits, historical corrupt output,

- The skipped item is the existing Windows file-symlink capability check.

## Upgrading and boundaries

- Storage stays at schema v5. Back up projects before upgrading. No manuscript,
  glossary seed, source identity, or run identity is changed by this patch.
- If a historical edit is rejected, inspect the retrofit job and its source.
  Use the existing rollback/revalidation workflow; do not edit SQLite directly
  or bypass strict export to conceal an integrity warning.
- Lease `.lease.db` sidecars are intentionally retained for coordination. Do not
  delete them while any process could still be using the project. If ownership
  cannot be proven dead, automatic recovery refuses to guess.
- Receipts still do not provide authoritative target-language offsets or a
  complete entity/alias identity mapping. This patch fixes the reproduced edit
  corruption cases, not arbitrary same-spelling semantic ambiguity.
- New English/German 100K and whole-book literary-quality runs were not performed.
  The README's V4 Flash timings remain historical measurements. A passing audit
  does not certify literary quality or that the software has no remaining bugs.
- Builds remain unsigned. Visual source-range selection, per-edit diffs, live
  panel refresh, and gradual store/runner decomposition are separate follow-ups.
