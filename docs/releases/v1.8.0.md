# FolioLoom v1.8.0

Bounded native Pi supervision and framework-neutral translation workers.
Windows x64 portable EXE and ZIP are the supported builds.

## Native Pi supervision

- New native CLI and desktop full-book runs enable an embedded Pi supervisor.
  It approves contiguous batches, queries registered source evidence, identifies
  semantic risks, reviews selected candidates, and requests grounded local repair.
- The kernel retains source identity, budgets, structural validation, transactional
  commits and export gates. No shell, filesystem or SQL tools are exposed to the
  supervisor. Provider-API runs do not launch an external coding-agent CLI.
- Decisions are bounded and persisted. Candidate hashes bind accepted reviews to
  exact text; ordinary resume reuses valid decisions and cannot bypass a pause.
  Explicit CLI pause release records a reason and never waives validation.
- Task context reaches translation, research, repair and supervision, participates
  in admission estimates, and is checked on resume. The desktop saves it per run.
- Supervised translation receipts use constrained supplied identifiers and compact
  term-use fields; the host restores source positions and concept metadata.

## Refusal-context correction

- ✓ Partial mitigation for DeepSeek's mistaken copyright refusals: callers can
  supply truthful source and usage context through the desktop task-context field
  or `--task-context-file`. This addresses missing-context assumptions, not provider
  policy, and neither guarantees acceptance nor invents copyright authorization.

## External workers and reliability

- A versioned JSON worker contract separates the host using the translation skill
  from the framework/model performing translation. OpenCode and Claude Code bridge
  recipes are included; external workers remain explicit opt-in CLI workflows.
- Worker profile/model identities are checked on resume. Native multi-tool
  supervision cannot be combined with an external worker.
- EPUB paragraph validation ignores whitespace-only boundary spans without
  weakening content, interior paragraph or structural-marker checks.
- Rejected repair responses retain their reported usage. Provider/account/network
  failures stop at the infrastructure boundary; unknown usage blocks strict export.

## Compatibility

- The build-only `fast-uri` dependency is updated from 3.1.6 to 3.1.8, addressing
  [authority injection](https://github.com/advisories/GHSA-qw65-cvwx-89v3) and
  [host confusion](https://github.com/advisories/GHSA-58mr-gqgx-xq4g).
  The high/critical dependency gate passes; six moderate findings remain.

- Storage stays at schema v5. Existing runs retain their recorded backend and
  supervision mode; enabling supervision on an old run requires a new run.
- Semantic review is a model judgment, not a guarantee of literary quality.
  Historical 100K measurements do not include the added supervision workload.
- Windows builds remain unsigned. Back up projects before upgrading.

## Live validation

- Regression gates: 1040 core tests passed with one environment-dependent skip;
  74 renderer tests and 10 skill/bridge tests passed. Core/desktop type checks and
  the desktop production build passed.

- A 549-word synthetic two-chapter native Pi run completed in 74.1 seconds with
  six model calls and 21,418 reported tokens. TXT/EPUB strict export and artifact
  verification passed; resume performed no further model calls.
- A separate 96-word synthetic case exercised requested semantic review. It
  exposed ambiguous plan-only fields in the review schema; event-specific empty
  array constraints and explicit instructions corrected that protocol mismatch.
  The same durable run then completed review and strict export, preserving all
  eight calls and 28,606 reported tokens across the failed and recovered attempts.
- These bounded checks verify execution and accounting, not whole-book literary
  quality or a general reduction in provider refusals.
