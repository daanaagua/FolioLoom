# FolioLoom v1.10.0

## Source-planned native execution

Native CLI runs can select `--planning-mode source`. FolioLoom computes and stores
the complete source execution plan before invoking a provider. The plan depends on
source windows, chapter boundaries, source token estimates and source text hashes,
not generated planning judgments or model confidence scores.

Four-window frontiers decouple pending work from concurrency slots. Within a
frontier, completion of one task can admit the next while another task continues.
Each frontier retains a frozen knowledge snapshot and ordered atomic commits;
frontier boundaries still synchronize knowledge. This is bounded lookahead, not
unrestricted whole-book speculative execution.

Model planning calls are replaced by explicit host-authored journal records.
Ordinary complete source windows receive semantic review at the complete chapter
barrier; open sentence boundaries retain immediate window review. Grounded surface
conflicts and deterministic structural validation remain active. Every source-planned
run requires bounded native supervision and complete chapter review, and unresolved
quality, source integrity, knowledge or usage findings still block strict export.

Source planning uses the configured baseline translation context and effort instead
of enumerating knowledge-dependent context/effort variants. Terminology can still be
translated by the model and used as translation data; it cannot repartition the stored
source execution plan. Adaptive concurrency and token admission remain active.

```sh
npm run folioloom -- book run --manifest project/source_manifest.json --store project/book.db --config model.yaml --planning-mode source --scheduler-mode active --max-concurrency 2 --output project/export
```

The CLI enables bounded chapter review for this mode. Source-plan identity survives
partial runs and restarts; switching modes requires a separate run. Existing native
and external-worker runs retain their recorded behavior. The mode is an explicit
CLI/core option and does not change desktop task defaults.
