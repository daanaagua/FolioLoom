# FolioLoom v1.7.0

FolioLoom v1.7.0 adds live terminology control, source-range rendering rules, and audited
batch correction for long-running book translations. The new control plane is shared by the
Electron workbench, CLI, and repository-scoped Codex skill.

## Live terminology control

- Terminology edits submitted while a translation window is running are durably queued and
  applied once at the next safe wave boundary. In-flight requests retain their original
  knowledge snapshot.
- Conflicting edits to the same knowledge object are rejected explicitly. Queue state and
  cancellation survive process restarts.
- Static glossary files remain immutable run seeds; manual corrections are stored as higher
  authority, versioned knowledge rather than rewriting run identity.

## Scoped rendering rules

- One entity or term can use different Chinese renderings over inclusive immutable source
  block ranges.
- Rule precedence is deterministic. Stale block endpoints, source-version drift, and
  equal-precedence overlaps are rejected before they can affect translation.
- Partial overrides project the default rendering only to blocks where it still wins.

## Audited retrofit jobs

- A dry-run plan identifies affected blocks and locks generation, snapshot, translation
  versions, classifications, and a canonical plan hash before execution.
- Receipt-backed, unambiguous locked surfaces are repaired locally into a new translation
  version. Missing or ambiguous receipts reuse the existing sparse model-revalidation path.
- A source form associated with more than one concept is never modified by blind target-side
  replacement.
- Jobs and items are durable and resumable. Unexecuted plans can be cancelled; completed or
  attention-required jobs can restore prior rule and translation versions without deleting
  history.

## Audit, desktop, CLI, and skill

- Strict export now blocks queued knowledge edits, pending active term impacts, unfinished
  retrofit items, attention-required items, and stale or missing concept coverage.
- The desktop “Terminology Control” panel shows the queue, impact summaries, planned local
  versus model work, job state, cancellation, and rollback.
- New typed CLI commands cover knowledge listing/upsert, queue status/cancellation, retrofit
  plan/apply/status/rollback, and UTF-8 JSON output.
- The repository-scoped `folioloom-translate` skill documents the same safe CLI workflow and
  never edits SQLite directly.

## Storage and compatibility

- Lossless schema v5 adds durable knowledge-change and retrofit tables plus scoped lexical
  projection metadata.
- Read-write opens migrate v2, v3, and v4 stores transactionally. Read-only opens do not
  mutate old stores, and injected migration failures preserve the previous schema intact.
- Existing source hashes, run identities, glossary hashes, translation IDs, and export
  lineage remain stable.
