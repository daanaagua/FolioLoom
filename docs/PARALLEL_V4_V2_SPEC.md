# parallel_v4 第二版规格

## 1. 目标

第二版在第一版影子流程上增加四类能力：段落级外部基线、本地Web裁决、高影响知识双重核验、局部修复与可选注释。第二版仍不把文学解释强制转化为唯一真相，也不修改旧章节JSON、旧译文文件或外部DOCX。

完整流程为：

```text
旧项目/外部DOCX
    → 非破坏性迁移与段落对齐
    → 证据扫描与保守归并
    → 高影响双重核验/人工裁决
    → 屏障式并行翻译
    → 确定性验证与局部修复
    → 盲评对照/可选注释
    → 严格导出
```

## 2. 外部基线

1. DOCX只读导入，保存绝对路径、SHA-256、段落数和导入时间。
2. 英文源文件与DOCX译文按非空段落一一对应；默认要求段落数完全相等。
3. 基线存储在独立表中，不写入翻译提示词，不参与术语自动裁决。
4. 文本块跨段落或在段落内部切分时，记录块与原书段落的交集以及首尾部分段落标记，不伪造句内精确对齐。
5. 对照界面优先使用指定外部基线；旧 `serial_v3` 仍作为次级基线。

## 3. 知识与假说

1. `claims`只保存可追溯陈述，类型包括翻译约束、时间约束、身份候选、揭示边界和解释假说。
2. 多个互斥假说可以同时处于 `proposed` 或 `disputed`，不得自动选出唯一解释。
3. 只有人工锁定或双重核验通过的翻译约束可以注入后续翻译。
4. 每条可注入约束必须有 `reveal_global_index`；在该位置之前不得注入，防止后文答案泄漏。
5. 时间线和叙述陷阱不是翻译前置条件。没有可靠证据时保持未决，不阻塞普通翻译。

## 4. 高影响双重核验

满足任一条件的建议进入高影响队列：

- 与现有默认译法冲突；
- 影响三个及以上文本块；
- 涉及人工锁定概念；
- 被明确标记为身份、时间或揭示边界约束。

高影响建议由两个相互独立的核验调用判断。两个调用都支持时才可标记为 `verified`；任一调用拒绝或不确定时进入人工队列。核验器只能引用给定原文证据，不得调用外部剧情答案。

## 5. 本地Web裁决

1. 服务只绑定 `127.0.0.1`，默认端口8765。
2. 所有写操作要求本次启动生成的随机令牌，防止其他本地网页跨站提交。
3. 页面至少展示人工队列、原文证据、候选译法、影响范围、质量警告、外部基线和当前译文。
4. 支持接受、拒绝、编辑后接受、上下文溢出重试、人工锁定、注释审批和修复请求。
5. Web界面是第一版 `review-v4` CLI 的可视化入口；所有操作仍通过同一数据库事务执行。

## 6. 局部修复

1. 验证器确定到单个文本块后，修复器只处理该块，不重翻全书。
2. 段落数不一致时，修复响应必须返回与原文完全等长的段落数组。
3. 修复器不能直接写数据库；协调器通过验证后提交新译文版本并保留旧版本。
4. 修复失败或结构解析失败时保留原译文，进入人工队列。

## 7. 可选注释

1. 注释与译文分表存储，状态为 `proposed`、`approved` 或 `rejected`。
2. 默认导出不含注释；只有显式启用时才把已批准注释写入TXT和EPUB。
3. 注释不得改写正文，也不得作为后文真相回灌翻译模型。

## 8. 验收

- 外部DOCX重复导入幂等，原文件哈希不变；
- 段落数不一致时默认拒绝导入；
- 《新日之书》英文源文和旧DOCX的11840个非空段落全部建立对应；
- Web服务不能绑定公网地址，缺少令牌的写请求必须拒绝；
- 高影响核验的两个模型结果均有独立审计记录；
- 未到揭示位置的约束不能进入上下文；
- 局部修复不覆盖旧译文版本；
- 默认导出不含注释，显式启用后只包含已批准注释；
- 第一版测试继续通过。
