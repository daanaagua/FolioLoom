# 多行标题中文词序修复设计

## 背景

FolioLoom v1.3.0 要求每个源段落对应一个目标段落，并禁止内容跨段移动。该规则能防止长篇翻译中的漏段、并段和跨块污染，但会误伤由多个版式行组成的标题。

例如源文：

```text
CHILDREN

OF TIME
```

当前模型按段翻译为：

```text
子

时间之
```

英语标题需要在中文中调整修饰语和中心词的顺序。当前提示禁止跨段调整，而验证器又接受上述错误结果，因此错误会进入数据库并原样导出。

## 目标

- 允许相邻的短标题或标题版式行作为一个语义单元翻译。
- 保持源段落槽位数量、槽位顺序和块边界不变。
- 允许标题组内部按中文语序重新分配词语。
- 普通正文继续禁止跨段移动、合并、拆分或重复。
- 首次翻译、兼容翻译路径和定向修复使用一致规则。

## 非目标

- 不修改原始文本或无损账本。
- 不在导出阶段猜测或重排译文。
- 不放宽普通正文的逐段完整性校验。
- 不为特定书名或英语短语添加硬编码规则。
- 本补丁不引入新的标题检测模型、数据库字段或结构标注类型。

## 方案比较

### 方案 A：提示词增加受限的标题组例外

在三个翻译提示入口加入同一条规则：相邻的短版式行若明显构成一个标题或小标题，模型可以整体理解并在相同数量的目标段落槽位内重新分配译文，但不得越过标题组或块边界。

优点：改动小；不迁移数据库；当前验证器已经接受 `时间 / 之子`；适合补丁版本。

缺点：标题组由模型判断，无法像显式结构元数据一样做到完全确定。

### 方案 B：放宽段落数量验证

允许多行标题合并成一个目标段落。

优点：可以直接输出单行《时间之子》。

缺点：会削弱漏段和并段防护；需要可靠的标题识别与分组元数据，不适合小版本。

### 方案 C：导入时识别并合并标题行

在源文本账本或分块阶段将多行标题表示成一个语义段落。

优点：长期结构最清晰。

缺点：TXT 中版式行与真实段落难以可靠区分；会改变源坐标、哈希或衍生计划，影响恢复和兼容性。

## 选择

v1.3.1 采用方案 A。方案 B 和 C 留给未来具有显式布局组元数据的版本。

## 行为设计

翻译约束调整为：

1. 保持目标段落槽位与源段落槽位数量相同、顺序相同。
2. 普通正文内容不得跨段或跨块移动。
3. 唯一例外是相邻的短版式行明显共同构成一个标题或小标题时：
   - 将整个标题组作为一个语义单元翻译；
   - 为符合自然中文语序，可在组内重新分配词语；
   - 仍输出与源标题组相同数量的非空段落；
   - 不得越过标题组边界或块边界。

示例：

```text
CHILDREN        时间

OF TIME     ->  之子
```

## 修改范围

- `folioloom/src/agents/translation-request.ts`
  - 更新正式整书批量翻译的系统提示。
- `folioloom/src/agents/translator.ts`
  - 更新兼容的 island 翻译提示。
- `folioloom/src/agents/repairer.ts`
  - 更新定向修复提示，避免修复过程恢复错误词序。
- 相关测试文件
  - 验证三个入口都包含标题组例外。
  - 验证正确的两行中文标题通过现有验证器。
  - 验证合并成一个段落仍被拒绝。
  - 验证普通正文逐段约束仍保留。

## 测试与发布门禁

1. 先增加失败测试，证明当前提示缺少标题组例外。
2. 最小修改三个提示入口，使目标测试通过。
3. 运行翻译请求、翻译代理和批量翻译相关测试。
4. 运行完整 FolioLoom 测试、类型检查和构建。
5. 使用 `CHILDREN / OF TIME` 做一次真实模型首窗口试译，确认输出为自然中文词序且仍保持两个段落槽位。

## 风险与控制

- 模型可能把普通短段误判为标题：提示要求“明显构成一个标题或小标题”，并限定为相邻短版式行。
- 模型可能合并标题段落：现有 `paragraph_count_incompatible` 校验继续拒绝。
- 三个提示入口发生漂移：测试分别覆盖正式翻译、兼容翻译和修复提示。
- 真实模型仍可能不遵循新提示：真实首窗口试译作为发布门禁，不以单元测试替代。
