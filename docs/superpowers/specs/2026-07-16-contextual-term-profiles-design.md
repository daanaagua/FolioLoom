# 语境化术语档案设计

## 目标

解决反复出现但表面上属于普通名词的翻译敏感词被扫描器拒绝、随后在正式译文中自由漂移的问题。首个回归案例是《新日之书》的 `torturer`：它既是职业身份和行会成员称谓，又必须与 `executioner`、`headsman`、`carnifex` 保持区别。

## 根因

当前候选裁决只允许命名实体或虚构术语，并明确要求拒绝普通名词。`torturer` 虽被词法扫描命中一百余次，却被模型以 `common noun` 为由拒绝，因此没有工作译名、语境规则或译后约束进入翻译阶段。

## 设计

### 1. 扩充候选类型

候选裁决增加 `role` 类型。反复出现、承担人物身份、制度、职业或社会阶层含义，并且需要全书稳定翻译的普通名词可以被提升为 `role`。普通动作、一般物品和不承载作品特定含义的高频词仍然拒绝。

裁决提示词必须明确：

- “普通名词”不是自动拒绝理由；
- 反复出现的职业、身份、阶层和制度称谓属于有效术语；
- 只有无需全书协调的普通名词才拒绝。

### 2. 术语档案

在 SQLite 中增加 `term_profiles`，依附于 lexeme 或 concept，保存：

- `semantic_core`：非剧透的词义边界；
- `contrast_sources_json`：必须保持区别的原文词；
- 知识版本、状态和锁定信息。

工作译名仍保存在现有 `lexemes/concepts` 中；语境译名仍使用 `rendering_rules`。允许译名集合由核心译名和全部有效规则目标共同构成，避免重复维护另一套译名列表。

目标解析模型的输出增加：

- `semantic_core`
- `contrast_sources`

例如：

```json
{
  "concept_id": "Q01",
  "working_target": "拷问者",
  "semantic_core": "以审讯和施刑为职业的行会成员；不要自动等同于执行死刑者。",
  "contrast_sources": ["executioner", "headsman", "carnifex"],
  "rules": [
    {
      "condition": {"discourse_function": "vocative"},
      "target": "拷问官"
    }
  ],
  "confidence": 0.94
}
```

目标解析采用两段式：

1. 第一段根据经过挑选的全书语境生成工作译名和语义档案；
2. 对 `role` 再运行一次独立双语词义/中文语域复核，纠正相邻职业混淆、机械造词和把人物所属组织写进词义核心的问题。

语境不再机械截取最早三处，而是保留：

- 最早出现；
- 自我定义、直接称呼等定义性语境；
- 含 `not / rather / but` 等区别信号的后文语境。

外部旧译只作为非权威措辞证据：当旧译用词符合英文词义边界和显式对照时可以采用，否则不得继承。

对于已经提升为 `role` 的单词，只吸收原文中实际出现、且由保守英语名词规则可确定的安全复数形式，例如 `torturer → torturers`。不执行通用词形猜测。

### 3. 翻译注入

冻结的渲染快照包含术语档案。正式翻译提示词中，每个命中术语显示：

- 当前语境决定的译名；
- 非剧透语义边界；
- 必须保持区别的原文词；
- 当前命中的语境规则。

不为每个词添加正文内标记，继续使用块级紧凑术语表。

### 4. 译后核验

新增纯本地 `TermConsistencyValidator`：

- 对每个已命中的术语，收集核心译名与有效语境规则目标；
- 如果最终译文完全没有出现任何允许译名，产生 `term_target_missing` 警告；
- 同一 lexeme 的不同 concept 分开校验，不共享允许译名集合；
- 如果一个文本块同时命中互为对照的术语，而知识库为它们配置了同一中文目标，产生 `term_contrast_target_collision` 警告；
- 警告使文本块进入 `completed_with_warnings`，但不阻断无人值守全书流程。

第一版不做自动逐句替换或强制修复。警告进入现有修复/人工队列体系，实际试跑后再决定是否增加局部自动修复。

## 非目标

- 不建立通用英语词形还原器；
- 不自动合并任意单复数形式，只吸收已观察到的安全职业名词复数；
- 不把所有高频普通名词写入术语库；
- 不允许术语档案泄露后文身份或叙事谜底；
- 不把 `torturer` 之类具体词硬编码进生产代码。

## 验收

1. `role` 是合法裁决类型，提示词不再因普通名词身份自动拒绝反复职业称谓。
2. 工作译名决定可以原子写入语义边界和对照词，重复写入保持幂等。
3. 冻结快照和翻译术语表包含档案信息。
4. 译文缺少允许译名时产生结构化警告并保留译文。
5. 原有命名实体、上下文规则、知识版本和重新验证测试保持通过。
6. 概念合并不会丢失 concept 级术语档案，档案单独变化也会触发精确重校验。
7. 用《新日之书》试跑时，后文 `carnifex / executioner / headsman` 的明确区别进入档案，`torturer/torturers` 共用约束。
8. 导入旧译作为非权威措辞证据后，Flash 试跑把自称句稳定译为“我是个拷问官”，不再静默漂移为“刽子手”。
