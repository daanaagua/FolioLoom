# FolioLoom 滚动动态规划调度器设计

日期：2026-07-27  
状态：已确认设计，待实现计划  
目标版本：FolioLoom 1.5  
适用范围：普通长篇翻译、知识回溯重译和上下文装配

## 1. 背景

FolioLoom 当前已有两类调度逻辑：

1. `window-planner.ts` 使用一维动态规划，在固定目标长度、最大长度和结构
   边界惩罚下选择逻辑窗口切点；
2. `AdaptiveScheduler` 使用简单 AIMD 规则，根据成功或拥塞调整并发。

这两者尚未联合考虑以下决策：

- 分块或合批后的真实运行时间；
- 不同推理强度的时间、token 与失败率；
- 给翻译模型提供多少结构化知识；
- 哪些校验应当立即执行；
- 哪些互不依赖的知识回溯任务可以并行；
- 缓存命中、供应商限流和近期吞吐变化。

2026-07-27 的《变形记》真实知识回溯验证中，5 个文本块精确重译约耗时
8 分 12 秒，相当于原始翻译墙钟时间的 52.9%。任务定位足够稀疏，但
revalidation drain 完全串行，且所有任务均使用 `quality/high`。这证明
主要瓶颈已经从“找到哪些块”转移到“如何执行这些块”。

## 2. 目标

本设计在不放宽质量与完整性约束的前提下，联合优化：

- 墙钟完成时间；
- 输入、输出、缓存和推理 token；
- 失败后返工成本；
- 提示词上下文的信息覆盖率；
- API 并发与在途 token。

三个用户模式的硬上限为：

| 模式 | 相对基线 token 增幅上限 | 主要目标 |
|---|---:|---|
| 经济 | 5% | 优先合批、缓存与低成本执行 |
| 均衡 | 10% | 默认平衡时间和 token |
| 极速 | 20% | 在质量门内优先缩短墙钟时间 |

这里的“基线”是同一模型、同一任务集合和同一质量门下，由 FolioLoom
1.4 稳定静态策略生成的预计 token。滚动规划同时维护“已实际使用”和
“尚未执行的保守预测”，两者之和不得超过累计基线包络。项目结束时以供应商
返回的实际 usage 复核；usage 不完整时只允许继续采用更保守的经济候选。

质量风险是硬约束，不允许通过提高目标函数中的其他收益来抵消。任何低于
任务最低推理强度、缺少强制证据或跳过必需校验的候选方案都不会进入求解器。

## 3. 非目标

本轮不做以下工作：

- 不更换翻译模型；
- 不允许规划器直接修改知识结论；
- 不取消顺序提交、无损原文、知识收敛或严格导出门；
- 不用 LLM 自己决定并发、预算或数据库事务；
- 不尝试一次性求解整本书的全局最优并行计划；
- 不在 GUI 暴露动态规划参数、权重和内部状态。

## 4. 总体架构

```text
逻辑窗口 / 术语锚定 / 回溯任务 / 校验任务
                       │
                       ▼
                TaskGraphBuilder
                       │
             有向无环任务图与硬约束
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
 ContextProfilePlanner       RuntimeCostModel
  内层上下文背包规划          在线时间/token/失败估计
          └────────────┬────────────┘
                       ▼
             RollingHorizonPlanner
            外层滚动动态规划调度
                       │
                下一批执行动作
                       │
                       ▼
               ExecutionKernel
        既有事务、校验、提交与恢复机制
                       │
                       ▼
                 数值遥测反馈
```

规划器只决定执行方法，不拥有数据库写权限。所有任务领取、翻译版本切换、
知识快照推进和校验仍由现有 kernel 与 store 方法完成。

## 5. 任务图

### 5.1 任务类型

统一任务图至少支持：

- `translate`：普通逻辑窗口翻译；
- `lexical_anchor`：当前波次术语与实体锚定；
- `revalidate`：知识变化后的 noop、repair 或 retranslate；
- `validate`：结构、术语、跨块和知识覆盖校验。

每项任务包含稳定 ID、输入来源、所属窗口、概念 ID、知识快照、预计原文
token、风险向量和依赖 ID。图中只记录调度所需元数据，不复制正文。

### 5.2 依赖规则

- `lexical_anchor` 必须先于消费其结果的翻译任务；
- 普通翻译可在同一知识快照内并行生成，但仍按窗口顺序提交；
- 修改同一窗口的两个任务不能并行；
- 修改或验证同一概念版本的任务不能并行；
- 依赖新知识快照的任务必须等待该快照提交；
- 不共享窗口、概念或快照写依赖的回溯任务可以并行；
- 校验失败只使直接依赖其结果的任务失效，不取消无关任务。

任务图出现循环或引用不存在的窗口、概念、快照时属于完整性事故，必须停止
并返回确定性错误；这类损坏不能靠旧调度器绕过。只有任务图合法、但成本
模型或动态规划求解器不可用时，才允许退回现有调度器。

## 6. 内层：上下文档案动态规划

### 6.1 候选信息单元

提供给翻译模型的信息划分为：

- 强制固定信息：系统协议、输出协议、用户文风宪法；
- 强制任务信息：待译原文、锁定术语、明确命中的高风险证据；
- 可选局部信息：相邻译文、近期叙事记忆、局部风格观察；
- 可选远程信息：实体关系、整体与局部、控制与归属、因果、时间线、
  叙述视角和人物已知信息；
- 恢复信息：前次失败类型、需要修复的具体校验项。

关系信息不能拆成失去语义的孤立字段。“实体—关系—实体”或“整体—部件”
作为一个 evidence bundle 进入候选集合。

### 6.2 成本与效用

每个 bundle \(i\) 包含：

- token 成本 \(c_i\)；
- 对当前任务的相关度；
- 对风险维度的覆盖集合 \(K_i\)；
- 证据置信度；
- 原文距离与位置可靠性；
- 与其他 bundle 的重复组；
- 必选依赖。

基础效用使用固定、版本化的数值函数：

\[
U_i =
w_k\cdot Coverage_i+
w_e\cdot ExactHit_i+
w_c\cdot Confidence_i+
w_d\cdot e^{-Distance_i/\tau}+
w_h\cdot HistoricalBenefit_i
\]

其中 `Coverage` 表示风险覆盖，`ExactHit` 表示当前原文准确命中，
`HistoricalBenefit` 来自同类信息过去是否减少 repair。首个版本使用固定
权重；只有积累足够跨项目样本后，才能在不改变硬覆盖门的情况下校准权重。

在预算 \(B\) 下选择集合 \(X\)：

\[
\max_X \left(
\sum_{i\in X}U_i-\rho\cdot Redundancy(X)
\right)
\]

约束：

\[
\sum_{i\in X} c_i \le B
\]

并要求当前任务的所有强制风险维度均被覆盖。重复内容按 canonical hash 和
语义组去重；同一风险维度的第二、第三条证据使用递减收益，避免把预算全部
消耗在一个实体上。

实现上使用 token 桶与风险覆盖 bitmask 的多约束背包动态规划。风险维度
数量固定且很小，状态不会随全书实体数量增长。

### 6.3 三种上下文档案

每个任务输出经过帕累托裁剪的三个档案：

- `lean`：局部原文、锁定术语、强制风险证据；
- `balanced`：加入相关实体关系和近期叙事记忆；
- `rich`：加入远程因果、时间线、视角与更多原文证据。

档案名称表示预算层级，不表示固定模板。不同任务的 `lean` 内容可以不同。
如果 `lean` 无法覆盖硬风险，它不会被生成。

固定系统提示词与稳定术语前缀独立于动态档案序列化，以保留供应商前缀缓存。

## 7. 外层：滚动动态规划调度

### 7.1 滚动范围

默认观察未来 \(H=12\) 个任务，最大允许 \(H=16\)。只选择任务图中已经
满足前置依赖或将在当前小范围内满足前置依赖的任务。全书长度不会进入
求解器状态。

每个任务生成有限候选执行变体：

```text
逻辑分块/合批 × 上下文档案 × 推理强度 × 协议 × 校验策略
```

候选先做帕累托裁剪。如果方案 A 的预计时间、token 和风险均不优于 B，
A 被删除。

现有 `quality/fast` 运行参数在迁移期间继续可读：`quality` 默认映射为
“均衡”，`fast` 默认映射为“极速”。新数据库持久化独立的
`optimizationProfile`，恢复旧运行时仍使用原来的固定 runtime，不在中途
改变语义。新运行的 runtime set 从“primary/escalation 两档”扩展为同一
模型的一组合法推理强度；风险门再从中删除不允许的低强度候选。

### 7.2 目标函数

对当前状态 \(S\) 和下一批兼容动作 \(B\)：

\[
V(S)=\min_B\left[
\hat T(B)+\lambda\hat C(B)+\mu\hat R(B)
\mathbb E[V(S')]
\right]
\]

其中：

- \(\hat T(B)\)：并行批次的预计 P90 墙钟时间，主要由最慢任务决定；
- \(\hat C(B)\)：预计输入、输出、缓存写入和推理 token；
- \(\hat R(B)\)：失败概率乘以拆块、重试、协议切换和升级推理的预计成本；
- \(S'\)：完成该批任务后的状态。

质量门、上下文上限、模型能力、最大并发、最大在途 token、任务依赖和
用户 token 增幅上限均为硬约束。

### 7.3 求解状态

小范围状态包含：

- 已完成任务 bitmask；
- 已使用 token 桶；
- 当前可用并发槽和在途 token；
- 已固定的运行中任务及预计剩余时间；
- 当前模式和供应商拥塞档位。

每个 bitmask 只保留有限数量的 epsilon-Pareto 标签：

```text
(预计时间, token, 返工风险, 动作链)
```

完全支配的标签立即删除。每个状态最多保留 8 个标签，每个调度点最多枚举
24 个批次候选。\(H\le12\) 使用完整子集动态规划；\(13\le H\le16\)
使用同一转移规则与有界 Pareto frontier，超时即返回当前最优可行解。

规划中的“批次”只用于预测。执行器不等待整批全部结束：任何任务完成后，
把尚在运行的任务作为固定资源占用并立即重新规划，因此不会形成实际的
同步屏障。

## 8. 风险模型

任务风险由本地确定性特征生成，不调用额外模型：

- 实体、别名和代词密度；
- 整体与局部、控制与归属关系；
- 因果和时间线命中；
- 叙述视角或人物已知信息变化；
- 锁定术语与多种允许表面形式；
- 远距离证据；
- 历史 repair、协议失败和完整性警告；
- 源语言、文本长度和异常字符；
- 当前知识是否为 `needs_revalidate`。

风险模型输出最低上下文覆盖、最低推理强度和必需校验集合。风险分数只用于
在合法方案之间排序；硬门由具体维度触发，不能被平均分稀释。

## 9. 运行成本模型与在线校准

### 9.1 时间模型

每个模型、语言、协议和任务类型分别维护：

\[
\log T=
\beta_0+\beta_1 I+\beta_2 O+\beta_3 E+
\beta_4 K+\beta_5 Q+\beta_6 L+\epsilon
\]

其中：

- \(I/O\)：预计输入和输出 token；
- \(E\)：推理强度；
- \(K\)：前缀缓存命中比例；
- \(Q\)：当前并发、在途 token 和拥塞状态；
- \(L\)：语言、任务类型、合批数量和风险档位。

参数使用带指数衰减的递归最小二乘更新；P50 用于一般估算，P90 用于调度
约束与完成时间展示。近期供应商状态权重高于数周前样本。

### 9.2 Token 与失败模型

- 输入 token 使用现有语言感知 estimator，并由供应商 usage 反校准；
- 输出 token 使用源语言、目标语言、任务类型和历史长度比估算；
- 失败概率使用带先验收缩的轻量逻辑模型；
- 样本不足时使用保守的模型/语言默认先验；
- 失败请求没有完整 usage 时将 `tokenUsageComplete=false`，不得伪造精确值。

供应商对 reasoning 或 cache token 的口径不同时，先归一化成互不重复的
usage 分量。用户的 token 上限使用归一化总量；目标函数还可依据供应商公开
价格给 cache read 较低的成本权重，但价格权重不能扩大 token 硬上限。

### 9.3 持久化与隐私

SQLite 新增或扩展的统计记录只保存：

- 模型与语言标识；
- 数值特征；
- 预计值和实际值；
- 失败类别；
- 调度模式和动作 ID；
- 时间戳与衰减权重。

不保存 API Key、完整提示词或额外正文副本。不同小说可复用同一模型与语言
档案，因此不会要求每本书重新冷启动。

## 10. 执行与提交

- 规划器返回动作描述，ExecutionKernel 负责实际领取任务；
- 同一窗口、概念或快照写依赖使用互斥资源键；
- 普通翻译可以乱序生成、暂存，仍由 CommitCoordinator 顺序推进；
- 回溯替换继续使用单事务版本切换；
- 每个模型请求完成后立即写入数值遥测并触发重规划；
- 尚未发出的旧计划可丢弃，运行中的任务不得因普通预测偏差强制取消；
- 用户取消、预算耗尽和外部服务故障仍遵循现有退出语义。

## 11. 故障恢复

候选执行变体预先包含允许的恢复边：

| 失败 | 恢复 |
|---|---|
| 低推理输出未通过校验 | 提高推理强度 |
| typed tool 协议错误 | 切换 framed text |
| 上下文容量错误 | 沿无损块边界拆分 |
| 限流、服务繁忙 | 降低同供应商并发并延迟重发 |
| 局部语义校验失败 | 只重跑相关文本块 |
| 成本模型损坏或求解超时 | 回退现有 AdaptiveScheduler |

恢复始终受现有最大尝试次数、预算和人工处理门约束。相同错误与相同形状不能
无限重新入队。

## 12. GUI

GUI 只增加：

- “经济／均衡／极速”选择；
- 预计剩余时间；
- 预计 token 区间；
- 实际耗时和 token 相对预测的偏差；
- 当前因限流、校验或上下文拆分而调整计划的简短状态。

用户无需设置 \(\lambda\)、\(\mu\)、滚动范围、token 桶或 Pareto 标签数。
高级 CLI 可以输出调度诊断 JSON，但不默认展示内部公式。

## 13. 测试

### 13.1 数学正确性

- 对 6–8 个任务穷举全部合法方案，与动态规划最优值比较；
- 属性测试保证 token 上限、依赖、互斥、质量门和任务唯一领取；
- 相同任务图、统计快照和模式必须输出相同计划；
- 上下文背包结果必须覆盖全部强制风险且不超预算。

### 13.2 离线重放

使用《变形记》既有五块回溯的任务长度、时间、调用和 token 遥测，比较：

- 现有串行调度；
- 固定并发；
- 滚动动态规划。

离线计划的预计墙钟时间必须低于当前串行基线的 50%。

### 13.3 供应商模拟

模拟：

- 正常延迟分布；
- 突发限流；
- 超时；
- 缓存命中与失效；
- 协议失败；
- 上下文拒绝；
- 速度随时间突变。

验证在线模型能够收敛、降低并发并停止重复失败。

### 13.4 真实样本

至少覆盖英语、德语、韩语和日语的短样本，以及一个既有长篇项目。比较质量
校验、人工处理率、时间和 token，不以单一语言结果替代多语言验证。

## 14. 性能与验收标准

- 12 个任务规划低于 50 ms；
- 16 个任务规划低于 250 ms；
- 规划内存只随滚动范围增长；
- 《变形记》五块回溯墙钟时间至少降低 50%；
- 长篇普通翻译墙钟时间目标降低 25% 以上；
- 均衡模式 token 增幅不超过 10%；
- 极速模式 token 增幅不超过 20%；
- 经济模式 token 增幅不超过 5%；
- 结构完整性、知识收敛和严格导出规则零回归；
- 校验失败率和人工处理率不得高于当前基线；
- 求解器失败时现有稳定调度器可完整接管。

## 15. 上线顺序

1. 实现数值遥测和离线成本模型，不改变执行；
2. 实现上下文档案规划，在影子模式比较现有上下文；
3. 实现外层动态规划，在影子模式记录计划与真实执行差异；
4. 为回溯任务启用“均衡”模式，验证独立任务并行；
5. 为普通翻译启用“均衡”模式；
6. 启用“经济”模式；
7. “极速”保留为实验选项，达到多语言验收后转为稳定功能。

任何阶段出现质量、完整性或人工处理率回归，立即关闭新调度并保留遥测用于
离线分析。
