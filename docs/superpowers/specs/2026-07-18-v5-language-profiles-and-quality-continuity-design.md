# V5 多语种语言画像与无损快路径质量连续性设计

## 1. 背景与问题

V5 无损全书路径已经能稳定完成源文本覆盖、窗口编排、并发执行和断点恢复，但《The Dragon Waiting》首窗口试跑暴露出一项结构性退化：该路径绕过了原有的术语锚定、前文风格尾巴和确定性翻译校验，只把旧版导入的 `stableTerms` 传给模型。新项目没有旧词库时，模型事实上在孤立翻译每个请求。

直接后果是同一人物的不同称名没有被统一。例如原文中的 `Loukianos of Samosata` 与 `Lucian the Scoffer` 指向同一人物，首轮译文却分别使用了“卢奇安”和“路吉阿诺斯”。数据库中的知识历史也为空，说明这些决定既没有在翻译前形成锚点，也没有在翻译后沉淀。

同时，当前若干模块把英语特征写死在正则表达式和提示词中。这与项目原本支持多语种小说的目标不一致，也会使法语、德语、西班牙语、俄语、日语等源文本无法共享同一套可靠的翻译架构。

本设计要解决的不是某个专名的硬编码，而是两个通用问题：

1. 让源语言差异成为可替换、可测试的语言画像，而不是散落在流水线中的特例。
2. 让无损快路径重新具备术语连续性、风格连续性和确定性质量门控，同时保留其低调用次数和并发能力。

## 2. 目标

- 在 V5 中引入统一的 `SourceLanguageProfile`，把分词、标题识别、词形归一、专名候选和源语言残留检测集中管理。
- 以英语和法语为首批完整实现，并提供德语、西班牙语等拉丁字母语言的共享能力与 Unicode 通用回退画像。
- 在无损路径中，每个并发波次只做一次有界术语锚定，所有并行请求共享同一份不可变锚点快照。
- 把上一已完成窗口的风格尾巴重新输入下一波翻译，且不让并行完成顺序改变上下文。
- 把确定性校验和一次有界局部修复接回快路径；单块失败不触发整窗重译。
- 让新语言信息进入源版本或派生计划身份，防止同一文件以错误语言画像复用旧计划。
- 保持源文件不被隐式改写；提取瑕疵只记录、报告并参与风险判断。
- 在干净数据库中重跑《The Dragon Waiting》首窗口，达到明确门槛后再启动全书。

## 3. 非目标

- 不在本轮重写 V4 流水线。
- 不试图一次实现所有语言的完整形态学分析。
- 不使用中间语言或机器桥接翻译。
- 不让模型解释整本小说的所有叙事陷阱后才开始翻译。
- 不自动修正所有 OCR、盗版页眉或断词瑕疵。
- 不把每个术语用行内标记塞回待译正文。
- 不为《The Dragon Waiting》的具体姓名、头衔或句子添加作品级硬编码。

## 5. `SourceLanguageProfile`

### 5.1 接口职责

语言画像是源语言智能的唯一入口。建议接口至少包含：

```ts
interface SourceLanguageProfile {
  id: string;
  version: string;
  displayName: string;
  locale: string;

  detectStructureHeading(line: string): StructureHeading | null;
  segment(text: string): SourceToken[];
  normalizeSourceForm(text: string): string;
  collectAnchorCandidates(input: CandidateCollectionInput): AnchorCandidate[];
  detectSourceResidue(translation: string): ResidueFinding[];
}
```

具体正则、停用词、大小写启发式和脚本检测不得继续散落到翻译代理、校验器和结构标注器中。调用方只依赖上述能力。

### 5.2 首批画像

- `en`：完整支持英语章节标题、大小写专名、所有格、缩写和拉丁字母残留检测。
- `fr`：完整支持法语章节标题、冠词/缩合词、重音字符、大小写专名和法语残留检测。
- `de`、`es`：复用拉丁字母基础画像，并各自提供标题模式、停用词和常见词形归一规则。
- `und`：使用 `Intl.Segmenter`、Unicode Script 属性和保守的重复片段统计；不依赖大小写存在，作为俄语、日语及未知语言的安全回退。

本轮不承诺 `und` 能像英语画像一样精确抽取专名，但它必须避免把非英语文本误套英语规则，并通过俄语、日语烟雾测试。

### 5.3 候选排序

候选收集同时考虑当前波次和全书轻量统计，使用确定性评分：

```text
score = firstOccurrenceWeight
      + log1p(corpusFrequency) * frequencyWeight
      + currentWavePresence * localityWeight
      + properNameConfidence * nameWeight
      + crossFormSimilarity * aliasWeight
      - noisePenalty
```

当前波次首次出现、但全书只出现一次的专名仍可入选；重复度不是唯一门槛。候选上限默认 24，可配置，但超出预算时只截断低分候选，不改变翻译正文。

画像只负责提出源形式和紧凑证据，不直接决定中文译名。别名合并仍由有界锚定模型结合上下文判断，避免用字符串相似度硬合并不同人物。

## 6. 源语言元数据与版本身份

### 6.1 清单字段

初始化命令增加：

```text
main.py init <project> <source> --source-language en
```

生成的 `source_manifest.json` 写入 `sourceLanguage`。新项目默认进行轻量检测并要求结果达到置信阈值；命令行显式值优先。为兼容既有英语项目，旧清单缺失该字段时按 `en` 加载，并在 doctor 中报告兼容模式。

### 6.2 身份规则

- 新清单：`sourceLanguage` 和画像版本进入规范化源身份或派生计划身份。
- 旧清单：缺失字段时保持旧版本计算行为，避免现有项目无端失效。
- 运行元数据记录 `profileId` 与 `profileVersion`。
- 同一原文字节若改用不同语言画像，必须生成不同的派生计划身份，不能静默复用旧窗口、锚点或校验结果。

关系数据库无需仅为此升级大版本；语言字段可进入已审计的源载荷 JSON 和运行元数据。现有 v2 数据保持可读。

## 7. 波次级术语连续性

### 7.1 执行范围

每个调度波次开始时：

1. 从将要执行的窗口收集当前候选。
2. 结合全书轻量频次索引和已锁定知识，去除已充分解决的源形式。
3. 对最高分的至多 24 个候选调用一次 `LexicalAnchorer`。
4. 生成不可变的 `WaveAnchorSnapshot`。
5. 同一波次的所有物理请求使用同一快照。

锚定不是逐窗、逐块或逐术语调用。它的调用次数随波次数增长，而不是随文本块数量增长。

### 7.2 别名与多译名

锚定结果允许：

- 多个源形式映射同一实体和同一首选中文形式。
- 同一源形式具有按语境选择的称谓变体。
- 暂不确定的候选保留为未锁定，不强行并入全局工作库。

翻译提示只接收本波相关的紧凑投影，而非整个数据库。一个锚点至少包含源形式、首选形式、允许变体、实体/概念标识和极短使用约束。

别名关系不再是一次性二元判断，而是带证据的追加式状态机：

- `provisional`：存在同一实体的可能，但证据不足；不得作为锁定术语强制投影。
- `confirmed`：直接命名、同位语或多项独立证据支持同一实体；不同表面形式共享 `conceptId` 和首选中文目标。
- `conflicted`：新证据与既有判断冲突；保留双方证据并触发定向重审。

字符串相似度只能生成候选边，不能独立确认实体。每条边保存显式命名、同位语、语境兼容、分布兼容、模型判断和矛盾惩罚等分量。后文出现新语境时，系统自动重审未决边；新确认的别名若与既有译文冲突，只生成漂移修复候选，不在知识事务中静默改写已经提交的译文。

### 7.3 原子持久化

锚点不能在翻译尚未成功时单独污染知识库。波次提交采用以下规则：

- 波次锚定结果先作为暂存工件保存，并带输入哈希。
- 每个成功窗口提交时，只持久化该窗口实际引用的锚点投影和模型提出的记忆候选。
- 同一锚点由波次中最早成功且实际引用它的窗口负责首次写入；后续窗口只追加证据。
- 若整个波次失败，暂存锚点不晋升为活动知识。
- 并发提交前做版本和冲突检查；完成顺序不得改变首选形式。

这样既能在干净项目中形成知识，又不会因为首个窗口失败而留下半成品状态。

## 8. 分层结构化风格

原始 `styleTail` 不再作为长期架构。有效风格由四层确定性合成：

```text
EffectiveStyle = BookStyleConstitution
               + VoiceProfile
               + DiscourseModeWeights
               + DecayingLocalState
```

### 8.1 全书风格宪法

`BookStyleConstitution` 是显式、版本化、不可由普通译文自动修改的全书规则，包括语域、句法处理、解释性增译、意象、对白、技术说明和排版策略。它来自项目配置或经批准的校准结果，不能由任意一个前序文本块反向塑造。

### 8.2 声音画像

`VoiceProfile` 具有位置安全的作用域，可区分主叙述者、人物声音、书信、文件和引文。系统只在叙事/实体记忆提供证据时切换声音；证据不足时使用声明的主叙述声音，不凭空猜测说话者。

### 8.3 混合话语模式

当前文本块不被强制归入单一类别，而使用归一化权重表达叙述、对白、动作、描写、技术说明、档案、抒情和内心独白等模式。模型前的确定性特征包括引号比例、段落形态、句长分布、数字/公式密度、括号密度和文件式布局。翻译提交可以在同一次模型调用中附加有界 `styleObservation`，不为风格另开一个代理调用。

### 8.4 衰减的局部状态

局部状态只保存活动语域、关系敏感的称谓选择、节奏观察、最近词汇选择和极短连续性注释，并按逻辑距离指数衰减、到期删除。它不能修改全书宪法。只有通过校验的译文才能产生风格观察；同一波次的并行兄弟共享波次开始时的不可变风格快照，波次结束后按逻辑序号合并。

系统最多检索两个已经通过校验、且声音和话语模式相容的短例文。没有合适样本时不提供例文，绝不使用题材不匹配的固定范文。最终发给翻译模型的只是 200～500 字左右的 `EffectiveStyleProjection`，而不是整份数据库或原始前文长尾。

风格状态与世界知识分开预算：前者解决“怎么写”，后者解决“写什么”。

## 9. 确定性校验与局部修复

### 9.1 校验项

`TranslationValidator` 接回无损快路径，并把英语残留判断改为画像调用。至少检查：

- 所有要求的窗口和块均存在且非空。
- 块 ID、顺序和源文本覆盖完整。
- 锁定术语与高置信锚点是否无故缺失或漂移。
- 是否存在异常源语言脚本残留。
- 引号、段落和边界数量是否明显失衡。
- 是否泄漏系统提示、JSON 协议或模型自述。
- 译文长度比是否越过语言画像和文本类型允许的宽松范围。

残留检测必须区分合法专名、缩写、公式和代码，不得简单以“出现任意拉丁字母”判失败。

### 9.2 一次局部修复

首次校验失败时，只把失败块、对应原文、相关锚点和精确错误码送入一次修复调用。修复后重新运行同一套确定性校验。

- 通过：正常提交，并记录修复审计。
- 仍失败：进入现有的类型化重试、暂停或人工队列策略。
- 不允许把失败块静默标为成功。
- 不因单块问题重译整个窗口。

## 10. 提示词与预算

所有提示词中的 “English forms” 改为 “source-language forms”，并显式提供画像 ID、源语言名称和目标语言。记忆候选协议保持语言中立。

单个翻译请求的上下文预算仍分层限制：

- 待译原文：主预算。
- 波次术语投影：只含命中或高风险条目。
- 按位置开放的叙事记忆：只含当前位置可见内容。
- 有效风格投影：固定小预算，只含当前声音、主要话语模式、局部连续性和至多两个匹配短例。
- 协议和校验约束：固定系统预算。

预算超限时按低相关记忆、低分术语、较早风格样本的顺序裁剪；不得裁剪待译原文、块边界或已锁定的命中术语。超过硬预算且无法安全裁剪时，返回人工处理，不改变内部语义规则。

## 11. 源文件异常报告

V5 doctor 增加只读异常统计：

- 疑似分页断词或空格断词。
- Unicode 替换字符和控制字符。
- 疑似重复页眉、盗版站点说明或非正文前言。
- 极端长行和异常章节标题。

《The Dragon Waiting》当前文本已观察到 `Beck- et's`、`Ma- chiavelli`、`Wood- ville` 等空格断词以及非正文页眉。首轮实现只报告并在运行记录中保留风险，不静默修改原文。后续若加入规范化层，必须保存原字节、规范化映射和可逆位置映射。

## 12. 兼容性与迁移

- 旧清单无 `sourceLanguage`：按英语兼容加载，并显示 doctor 警告。
- 已有 V5 数据库：不强制迁移历史锚点；新运行记录画像版本。
- 已有 `stableTerms`：作为高优先级既有知识参与波次投影，不被新锚定无条件覆盖。
- 旧提示协议产生的 `memoryCandidates`：保持可读；新写入使用语言中立描述。
- CLI、恢复和审计命令的默认行为保持不变。

## 13. 测试策略

### 13.1 单元测试

- 英语、法语、德语、西班牙语和 `und` 注册与选择。
- 英法章节标题与专名候选。
- Unicode 分词、重音字符、所有格和词形归一。
- 中文目标中的英语、法语、俄语、日语源脚本残留烟雾测试。
- 合法缩写、公式和专名不会被误判为残留。
- 旧清单缺字段的兼容行为与版本稳定性。

### 13.2 集成测试

- 干净项目在首个波次即可产生非空锚点或引用证据。
- 同一波次的并行请求收到相同锚点快照和相同前序风格尾巴。
- 并发完成顺序变化不改变最终知识状态。
- 单块校验失败只触发一次该块修复。
- 整波失败不会晋升暂存锚点。
- 恢复运行不会重复调用已缓存且输入哈希一致的锚定。

### 13.3 回归与性能测试

- 无模型测试套件全部通过。
- 现有 V5 全书 doctor、audit 和恢复测试不退化。
- 锚定调用数不超过波次数；局部修复只在校验失败时出现。
- 在相同窗口规模下，新增流程的模型调用和墙钟时间有单独报告，不允许退回逐块多代理扫描。

## 14. 《The Dragon Waiting》验收门槛

实现完成后删除本次有缺陷的测试运行和数据库派生工件，从原文重新初始化并只跑首窗口。满足以下条件后才继续全书：

- `Loukianos of Samosata` 与 `Lucian the Scoffer` 被确认成同一实体，或留下明确的 `provisional` 关系；不得静默成为两个互不相关的锁定实体。
- 对反复出现的关键姓名形成非空锚点/知识投影。
- 后续窗口实际收到由已验收逻辑状态生成的有界有效风格投影，而不是原始前文长尾。
- 确定性校验已执行，且没有系统泄漏、缺块或未处理的高风险残留。
- audit 无意外 incident，warning 只包含可解释的源文件异常。
- 性能仍符合快路径目标；若首窗口明显退回多分钟级多代理链，停止全书并分析调用账单。

通过首窗口后再运行两个相邻窗口，验证风格尾巴和并发确定性；三窗口门槛通过后，才以 Flash 启动全书 113 窗口运行。

意外下载到的法语译本只能用于多语种工程烟雾测试，不用于文学质量比较，也不代替英语原文的正式翻译。

## 15. 实施顺序

1. 增加语言画像接口、注册表和首批画像测试。
2. 把结构标注、候选收集、残留检测和提示词迁移到画像接口。
3. 增加清单语言字段、兼容加载和版本身份测试。
4. 在无损 runner 中接入波次级锚定和原子知识晋升。
5. 接入风格尾巴的确定性读取与更新。
6. 接回确定性校验和一次局部修复。
7. 增加源文件异常报告。
8. 运行无模型回归与恢复测试。
9. 清理《The Dragon Waiting》坏测试工件，依次执行一窗口、三窗口和全书门槛。

## 16. 风险与控制

- **锚定增加延迟**：限制为每波一次、候选有上限、输入哈希可缓存。
- **错误别名合并污染全书**：字符串算法只提候选，模型判断；未锁定项保留证据；冲突不自动覆盖既有锁定知识。
- **并发导致知识顺序不确定**：波次快照不可变，首次写入按逻辑序号决定。
- **残留检测误报**：画像返回带类型的 finding，校验器豁免缩写、公式和合法专名，并只局部修复。
- **语言识别错误**：显式 CLI 值优先，画像进入计划身份，doctor 显示实际画像。
- **上下文膨胀**：所有知识投影有上限，按相关性裁剪，不使用逐词行内标记。
- **源文本瑕疵影响译文**：先报告并保留原始坐标；自动规范化另立可逆设计。

## 17. 完成定义

本设计完成的标准不是“能调用多语种模型”，而是：

- 源语言差异已从核心流水线抽离为可测试画像。
- 干净项目无需旧词库也能在首波形成并使用术语连续性。
- 并行翻译具备稳定的术语快照和风格前态。
- 失败块经过确定性校验和一次局部修复，不会静默混入成品。
- 旧项目仍可加载、恢复和审计。
- 《The Dragon Waiting》通过一窗口与三窗口门槛后完成 Flash 全书运行。
