# FolioLoom 知识工作台与持久化导入设计

**日期：** 2026-07-23

**状态：** 交互方案已确认，实现计划已拆分

**适用范围：** Electron 桌面端、V5 SQLite 知识库、术语/实体/关系/叙事记忆/风格数据的查看、编辑与导入

## 1. 背景

FolioLoom 已经使用 SQLite 保存预扫描候选、已确认知识、证据、快照和翻译状态，但普通用户目前无法直观地查看或修正这些数据。已有 JSON 术语表只能表达较简单的“原词—译词”关系，YAML 主要用于风格配置；任意 JSON、YAML、CSV、XLSX 尚无统一导入入口。

直接允许用户修改 SQLite 虽然看似自由，实际上会绕过版本、证据、作用域、快照、激活状态和影响分析，容易形成“界面显示已经修改，翻译运行却仍读取旧投影”的隐蔽错误。因此，桌面端需要提供语义化知识工作台：用户编辑“术语、人物、别名、关系、记忆、风格”等对象，由应用命令层负责安全、可追溯地写入 SQLite。

本设计采用已经确认的两层交互：

1. 知识工作台以表格为主视图，右侧抽屉显示详情、证据和版本历史；
2. 导入向导支持 FolioLoom 模板直接导入，以及任意 JSON/YAML/CSV/XLSX 的字段映射、预览、冲突处理和原子提交。

## 2. 目标

- 让没有数据库或编程经验的用户可以查看、筛选、编辑并撤销知识数据。
- 让人工修改、外部导入和模型扫描结果长期保存在项目 SQLite 中，并真实参与后续翻译。
- 默认将修改限制在当前书籍；用户可显式提升为通用术语，供其他项目复用。
- 允许导入结构不同的 JSON、YAML、CSV 和 XLSX，而不要求用户手工修改协议或数据库。
- 所有修改均有来源、版本、证据、作用域和审计记录。
- 导入失败时不产生半成品；冲突不确定时可以暂存，不能静默覆盖。
- 已完成译文不因知识修改被暗中重写，但应标记可能受影响的文本块。
- 在长篇项目中保持分页、筛选和导入性能稳定，不一次性把整个知识库送入渲染进程或模型。

## 3. 非目标

- 不提供任意 SQL 写入、数据库表结构编辑或 SQL 控制台执行能力。
- 不承诺自动理解所有第三方文件的语义；低置信映射必须由用户确认。
- 不把关系图作为主编辑界面，也不试图用一张图完整呈现长篇小说。
- 不用大模型直接生成 SQL 或直接写数据库。
- 不在知识修改后自动重译整本书。
- 不把项目级人物关系、叙事记忆无条件提升为全局知识。

## 4. 采用方案

### 4.1 知识工作台

主区域采用可分页、可虚拟滚动的表格，按对象类型展示：

- 术语；
- 实体（人物、地点、组织、器物等）；
- 别名与指代；
- 实体关系；
- 叙事记忆；
- 风格约束。

顶部提供搜索以及类型、状态、来源、作用域筛选。每一行显示最有用的字段，如原文形式、当前译法/名称、对象类型、作用域、状态、来源和最近修改时间。

点击一行后，右侧抽屉展示：

- 可编辑的语义字段；
- 支持该结论的原文证据与位置；
- 别名、关系和相关对象；
- 来源及置信信息；
- 版本历史；
- 可能受影响的已译文本块；
- 保存、撤销、合并、改变作用域等操作。

关系图只作为当前对象附近的一到两层辅助视图，不承担全库浏览和主要编辑职责。

### 4.2 导入向导

导入流程固定为四步：

1. 选择文件并识别格式；
2. 选择对象类型并映射字段；
3. 预览、校验和解决冲突；
4. 原子提交并生成导入报告。

FolioLoom 官方模板可跳过大部分映射。任意第三方文件由确定性规则先识别表头、路径和样例，再给出映射建议；用户可以修改建议。只有用户显式允许时，才可把少量字段名与脱敏样例交给模型辅助判断，模型不接触数据库，也不执行写入。

## 5. 数据所有权与持久化

SQLite 仍是项目知识的唯一事实来源。界面不维护与 SQLite 平行的 JSON 真相副本。

所有人工编辑和导入先进入应用命令层，再在单个事务中完成：

1. 校验对象模式、引用和作用域；
2. 写入新修订；
3. 写入来源、证据和审计事件；
4. 更新当前激活投影；
5. 增加知识代数 `knowledge_generation`；
6. 计算并记录可能受影响的翻译块；
7. 提交事务。

任一步失败，整个事务回滚。

### 5.1 作用域

默认作用域为 `book`。可选作用域包括：

- `book`：仅当前书籍使用；
- `project`：同一系列或同一翻译项目使用；
- `global`：用户明确保存为通用术语后，其他项目可以选择引用。

实体身份、剧情关系和叙事记忆默认禁止一键提升为 `global`；术语和风格条目可以提升，但必须显示目标范围并要求确认。

### 5.2 决策优先级

优先级按字段而非整条记录计算，避免为了修改一个译名而覆盖整个人物对象：

1. 当前书籍中用户确认的字段修订；
2. 当前书籍中用户确认的导入字段；
3. 当前项目中用户确认的字段；
4. 用户选择启用的全局字段；
5. 已锁定的模型裁决；
6. 尚未裁决的扫描候选。

同一级别出现不一致时，不以最后写入者静默胜出，而是产生显式冲突。用户可选择保留现有值、采用导入值、将新值并为别名、创建独立对象或暂不处理。

### 5.3 长期生效

保存成功的修订不会因重新打开应用、重新扫描或重新分块而丢失。重新扫描只能补充候选和证据，不能覆盖用户确认字段。

`book` 修订绑定当前书籍的 source version，并由同一本书后续创建或恢复的运行继承；`project` 修订保存在项目级 catalog 中，可跨该项目的 source version 使用；`global` 修订保存在用户级独立库中，只有用户明确附加后才以不可变快照进入某本书。运行自己的知识快照仍是实际翻译输入，启动或恢复时在安全边界同步较新的 book/project catalog generation，避免界面修改只停留在管理层。

翻译请求在构建术语与叙事记忆投影时读取当前 `knowledge_generation`。保存后的修改会用于后续尚未翻译的块；已经翻译的块只被标记为“可能受影响”，由用户决定是否局部重译。

## 6. 应用命令边界

渲染进程只能调用有限、类型化的命令，例如：

```text
CreateKnowledgeRecord
UpdateKnowledgeFields
AddAlias
MergeEntities
CreateRelationship
UpdateNarrativeMemory
ChangeKnowledgeScope
PromoteTermToGlobal
RollbackKnowledgeRevision
StageKnowledgeImport
CommitKnowledgeImport
RollbackKnowledgeImport
```

每个命令携带项目身份、对象身份、预期修订号和请求身份。预期修订号不匹配时返回并发冲突，不能覆盖其他窗口或后台扫描刚写入的修改。

主进程负责路径、数据库连接、事务和文件解析。渲染进程只接收分页数据、显示字段和 opaque ID，不接收任意数据库路径或 SQL 执行能力。

## 7. 导入格式

### 7.1 FolioLoom 模板

提供 JSON、YAML、CSV 和 XLSX 模板。模板包含版本号、对象类型、字段定义和可选作用域，可以直接进入预览。

### 7.2 任意 JSON/YAML

向导先识别：

- 顶层数组；
- 包含记录数组的对象路径；
- 键值对术语表；
- 嵌套对象；
- 单记录对象。

用户选择记录路径后，把源字段映射到 FolioLoom 字段。嵌套路径使用只读路径选择器完成，不要求用户编写表达式。

### 7.3 CSV/XLSX

- CSV 自动探测 UTF-8、UTF-8 BOM 和常见本地编码；不确定时展示预览并要求确认。
- XLSX 让用户选择工作表和标题行。
- 只读取单元格值，不执行宏、外部链接或公式。
- 多工作表可分别建立映射，但每次提交形成同一个可回滚导入批次。

### 7.4 映射建议

确定性建议综合字段名、数据类型、唯一性、样例分布和常见同义列名。建议带置信度：

- 高置信：自动选中，仍可修改；
- 中置信：高亮等待确认；
- 低置信：保持未映射。

模型辅助只用于给出候选映射和解释，不得改变已确认字段，不得直接提交。

## 8. 校验与冲突处理

提交前执行完整 dry-run，至少检查：

- 必填字段缺失；
- 空记录和重复记录；
- 非法对象类型或作用域；
- 同一源形式对应多个互斥译法；
- 别名引用不存在的实体；
- 关系端点缺失；
- 叙事记忆缺少生效位置；
- 文件编码或结构不明确；
- 导入规模超过安全边界；
- 与当前激活知识冲突。

预览将结果分成：

- 可直接新增；
- 可安全合并；
- 需要用户决定；
- 无法导入。

用户的冲突选择可批量应用于相同冲突类型，但必须显示影响条数和可撤销的导入批次。导入报告记录新增、更新、合并、跳过、待处理和失败数量。

重复导入同一个批次或内容哈希时应保持幂等：系统提示已导入，而不是制造重复实体。

## 9. 编辑体验

### 9.1 术语

编辑原文形式、首选译法、备选译法、语境限制、作用域和锁定状态。变体不是简单字符串数组，而是可附带语境、说话者/受话者、位置范围和证据。

### 9.2 实体与别名

实体详情集中显示规范名称、译名、类型、别名、描述和证据。合并实体必须预览被迁移的别名、关系、记忆和受影响块，并保留可回滚的合并修订。

### 9.3 关系

关系以“主体—关系—客体”表单编辑，可附带时间/位置范围、确定性和证据。关系图仅展示局部邻域。

### 9.4 叙事记忆

记忆条目必须显示内容、关联实体、生效起点、失效点或可见范围以及来源。界面明确区分“文本事实”“译者推断”和“开放解释”，避免把一种文学解读伪装为确定事实。

### 9.5 风格

风格编辑器提供结构化字段和最终预览，不直接暴露内部 prompt 模板。临时 `--prompt` 仍只附加本次运行的文风要求，不修改持久化风格档案。

## 10. 只读数据库检查器

高级诊断区可以展示表名、记录数量、数据库版本、最近迁移、当前知识代数和经过限制的只读查询结果。它的用途是排障和导出，不是编辑。

默认不展示底层表名和内部 ID；只有启用高级模式后才显示。任何写 SQL、PRAGMA 修改、附加数据库和扩展加载都不允许从界面执行。

## 11. 错误与恢复

用户可见错误必须包含：

- 发生在哪一步；
- 哪些记录受影响；
- 数据是否已经写入；
- 可以采取的下一步；
- 可用于日志检索的短错误编号。

导入使用 staging 区和原子提交。应用崩溃或被关闭后：

- 未提交 staging 可恢复预览或安全丢弃；
- 已提交批次保持完整；
- 用户可按批次撤销；
- 撤销本身生成新修订，不删除审计历史。

大文件解析、预览和提交均可取消。取消只在安全检查点生效，并明确显示最终状态。

## 12. 性能边界

- 表格使用服务端分页、索引筛选和虚拟滚动；
- 搜索不一次性加载全文证据；
- 证据和版本历史在打开详情时按需读取；
- JSON/YAML/CSV 尽可能流式解析；
- XLSX 按工作表和行范围分批处理；
- 导入预览只保留样例与聚合错误，完整 staging 留在主进程；
- 翻译时仍只投影当前文本块相关的术语、实体和记忆，不把整个知识库发送给模型。

建议索引覆盖对象类型、规范源形式、作用域、状态、项目身份、实体端点、位置范围和知识代数。

## 13. 安全与隐私

- 文件在本地解析，默认不发送给任何模型。
- 模型辅助映射必须由用户显式开启，并在调用前显示将发送的字段名和样例。
- API Key 不进入导入数据、日志、错误详情或渲染进程持久状态。
- XLSX 宏、外部链接和公式不执行。
- 导出和日志默认隐藏本机绝对路径、密钥和 provider 响应中的敏感头。

## 14. 测试策略

### 14.1 单元测试

- 各格式解析、编码处理和字段路径识别；
- 映射建议与置信度；
- 模式校验和错误定位；
- 字段级优先级与冲突分类；
- 作用域提升限制；
- 幂等导入和内容哈希；
- 命令乐观锁；
- 影响块计算。

### 14.2 属性与故障注入测试

- 任意失败点均不产生部分提交；
- 同一批次重复执行结果不变；
- 保存后重新扫描不能覆盖用户确认字段；
- 撤销后审计历史仍完整；
- 解析器面对深层嵌套、超长字段、公式、损坏压缩包和异常编码时有界失败。

### 14.3 集成测试

- 创建项目、编辑术语、关闭并重开应用，修改仍存在；
- 导入第三方表格、处理冲突、提交后翻译投影读取新值；
- 修改实体别名后，相关块被标记但旧译文不被静默替换；
- 将书籍术语提升为全局后，新项目可选择引用，原项目仍保留来源；
- 导入中断后恢复或丢弃 staging；
- 多窗口同时编辑同一修订时返回冲突。

### 14.4 桌面端端到端测试

至少覆盖：

1. 官方模板直接导入；
2. 任意 JSON 字段映射；
3. XLSX 工作表与标题行选择；
4. 冲突合并为别名；
5. 编辑、保存、撤销和重启持久化；
6. 只读数据库检查器不能执行写入；
7. 在试译中验证新术语和记忆确实进入模型投影。

## 15. 实施分层

建议按以下顺序实现：

1. 建立命令层、修订/导入批次数据模型、分页查询和字段级优先级；
2. 接通知识工作台表格、详情抽屉、证据和版本历史；
3. 完成官方模板和 JSON/YAML/CSV/XLSX 导入向导；
4. 接通冲突处理、撤销、作用域提升和影响块提示；
5. 增加局部关系图与高级只读数据库检查器；
6. 用真实项目完成“导入—编辑—翻译—重启—撤销”的端到端验收。

该顺序先保证数据真实、可恢复和可被翻译核心读取，再增加视觉辅助功能，避免先做出无法长期生效的界面。
