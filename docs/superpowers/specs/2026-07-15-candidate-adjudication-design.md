# 候选跨度裁决、工作译名与可控存储设计

日期：2026-07-15  
状态：待用户审查  
目标分支：`feature/parallel-v4-v2`

## 1. 背景与目标

当前 v4.2 扫描器已经解决了模型逐字复制原文时受弯引号、标点和段落定位影响的问题：本地程序生成候选及精确偏移，模型只返回短候选编号。然而一次候选分类仍同时承担边界选择、实体识别、类型判断和译名建议，导致三类可泛化错误：把 `Drotte and Roche` 当成单个人物、把 `Corpse Door` 截成 `Corpse`、把雕像主题 `Night` 强制归类为作品。

本设计的目标是：

1. 候选证据宽松保留，进入全局工作词库时优先保证精确率。
2. 不针对具体小说词汇写生产特例，使用通用跨度、聚类和裁决机制。
3. 不要求模型复制原文或管理字符偏移，所有定位由本地程序恢复和验证。
4. 正式翻译前为重复、高影响概念确定统一的暂定工作译名。
5. 每本小说使用独立 SQLite，并对活动数据库和完整审计设置可预测的容量边界。

本设计不负责解释叙述陷阱、建立完整时间线或人物关系网，也不把文学解释强制写入翻译约束。

## 2. 核心原则

候选库是不可丢失的证据层；工作词库是可修改的决策层。候选可以被拒绝、拆分、替代或延期，但不因并入工作词库而物理删除。

“尚未验证”不等于“正式翻译时不提供统一译名”。系统分别保存：

- `working_target`：本次全书翻译必须统一采用的暂定译名；
- `verified_target`：经过人工或独立核验后锁定的正式译名；
- `rendering_rules`：同一概念在呼告、机构指称等语境中的条件译法。

不确定候选不得成为工作译名约束。若自动模式无法安全裁决，候选保持 `deferred`；若该候选又是正式翻译不可缺少的高影响项，则返回人工处理，不允许模型在各文本块临场决定。

## 3. 数据层次

### 3.1 候选出现 `candidate_occurrences`

每次原文出现保存精确字符偏移、原始拼写、规范化形式、短上下文、提取原因和运行编号。记录原则上只追加，不参与日常全表扫描。

状态包括：

- `pending`：尚未裁决；
- `rejected`：普通词或无翻译价值；
- `promoted`：已支持某个工作概念；
- `superseded`：被更完整跨度取代；
- `split`：复合跨度已拆为多个候选；
- `deferred`：证据不足，等待更多上下文或人工处理。

### 3.2 候选跨度 `candidate_spans`

本地程序为一个可疑位置生成少量相互重叠的合法跨度，而不是立即决定唯一答案。例如：

```text
Drotte
Roche
Drotte and Roche

Corpse
Corpse Door
```

跨度来自通用规则：大写或异常词、相邻名词性成分、所有格和复数变体、并列结构的整体及原子成分。普通词可以作为专名的词首或语义中心，因此不能仅因 `Door` 常见就从完整跨度中删除。

### 3.3 候选簇 `candidate_clusters`

相同规范形式、确定性词形变化和高度相似的跨度被聚成簇。每个簇保存全部出现记录，但交给模型的只有最多三个代表性上下文，优先选择：首次出现、典型出现和结构异常出现。

### 3.4 裁决与概念

裁决结果为 `promote`、`reject`、`split`、`supersede` 或 `defer`。被提升的跨度通过证据关系支持 `concepts`；候选记录不移动、不删除。

实体类型允许保守的 `unknown_named_entity` 和 `concept`。`Night` 可以记录为“作为雕像主题出现的拟人概念”，而不必在证据不足时强制判断为作品、人物或神祇。

## 4. 模型输入与幻觉控制

模型不会看到每个单词的 `T001…T500` 编号。每次裁决调用最多包含 12 个候选簇，每簇最多 4 个合法跨度、3 个代表性上下文。数据库长 ID 映射为本次调用内的短别名，例如：

```json
{
  "cluster_id": "K03",
  "alternatives": [
    {"id": "K03A", "text": "Drotte"},
    {"id": "K03B", "text": "Roche"},
    {"id": "K03C", "text": "Drotte and Roche"}
  ],
  "contexts": ["...Drotte and Roche believed it was..."]
}
```

模型只能选择输入中存在的别名：

```json
{
  "cluster_id": "K03",
  "verdict": "split",
  "selected_ids": ["K03A", "K03B"],
  "entity_kind": "person",
  "confidence": 0.96
}
```

本地校验必须拒绝以下响应：未知 ID、跨簇引用、重复 ID、`split` 结果互相重叠、`supersede` 结果没有包含原跨度、跨度与原文偏移不一致、非法枚举和缺失必填字段。模型不得创建输入中不存在的新跨度；若格子中没有正确跨度，只能返回 `defer` 并标记 `missing_span`，由本地扩展器生成新跨度后再次裁决。

含并列连词的跨度不会被机械拆分，因为组织名和作品名也可能包含连词。但“并列跨度被判为单个人物”、类型跨上下文冲突、置信度不足和高影响概念必须进入第二次独立裁决。第二次调用看不到第一次结论，并重新排列本地短别名；两次不一致则保持 `deferred`，不能进入工作词库。

## 5. 裁决数据流

```text
原文块
  → 确定性候选出现与跨度网格
  → 跨块候选聚类
  → 第一轮 Flash 裁决
  → 本地结构校验
  → 风险分流
      → 低风险一致结果：promote/reject
      → 高影响、边界变化、类型冲突：独立第二轮
      → 两轮冲突或缺少正确跨度：defer
  → 形成高精度工作概念
  → 工作译名裁决
  → 冻结知识版本
  → 正式并行翻译
```

第二轮不是对所有候选重复扫描，只处理 `split`、`supersede`、高影响项、类型冲突和低置信度项。

## 6. 工作译名裁决

正式翻译前，所有重复人物、地点、组织、特殊单位和高影响人造概念必须有 `working_target` 或明确的人工阻塞状态。工作译名综合扫描建议、旧译文基线和代表性语境产生，但建议票数不能直接等同于正确性。

固定专名使用统一工作译名。语境敏感词使用默认译名和条件规则，例如：

```json
{
  "source": "Archon",
  "working_target": "执政官",
  "rules": [
    {"condition": "直接正式呼告对方", "target": "阁下"}
  ]
}
```

翻译运行读取冻结的知识版本。翻译过程中发现的新术语建议只暂存到下一道屏障，不能改变当前并行批次的提示。如果之后修改工作译名，所有依赖文本块都标为 `needs_revalidate`，包括提出该建议的当前批次。

## 7. 查询与规模设计

每本小说使用独立 SQLite。候选出现数量可以达到数十万，但活动队列默认只查询 `pending` 和 `deferred`。

当前逐块遍历全部 `source_forms` 并逐项编译正则的实现必须替换为按知识版本缓存的 Trie 或 Aho–Corasick 匹配器。匹配复杂度应接近文本长度加命中数量，而不是文本块数乘词库大小。

活动数据库硬上限定义为：

```text
book.db ≤ 40a + 64 MB
```

其中 `a` 是解压后的 UTF-8 原文文件大小。完整模型请求和回复按运行写入 `jsonl.zst` 审计归档；SQLite 保存哈希、偏移、状态和关键统计。单次完整项目的保守总预算为 `60a + 128 MB`。达到活动数据库硬上限时停止运行并返回人工处理，不静默删除证据。

大型迁移、重建索引或 `VACUUM` 可能临时需要约两倍活动数据库空间，启动前必须检查可用磁盘。

## 8. 旧试验数据重置

实现完成后，对 `new_sun_omnibus` 执行事务化扫描重置：

1. 保留源版本、原文块、段落、旧译文基线和人工锁定数据；
2. 删除当前试验运行生成的候选、扫描证据、未锁定暂定概念、未锁定规则、验证任务和扫描审计；
3. 将受影响文本块恢复为 `pending`；
4. 保留干净的源数据库备份，旧 v4.1/v4.2 试验快照在新小样通过后删除。

重置必须提供预览计数，并在一个事务中完成；任何外键或计数校验失败都回滚。

## 9. DeepSeek Flash 小样

使用与上一轮相同的前八块：两块前置材料由本地跳过，六块进入模型。先完成候选跨度、聚类和裁决，再生成工作译名；暂不运行全书正式翻译。

小样必须报告：

- 每轮调用的候选簇数、跨度数、上下文字符数和耗时；
- 未知 ID、非法组合、重试和终止失败数量；
- `promote/reject/split/supersede/defer` 数量；
- 精确原文偏移和外键完整性；
- 工作译名覆盖率及冲突；
- 与旧小样相比的概念差异。

回归重点：

- `Drotte and Roche` 不得成为单一人物概念；
- 若原文存在完整 `Corpse Door` 跨度，单独 `Corpse` 不得作为最终地点概念；
- `Night` 不得在证据不足时被强制登记为 `work`，允许保守提升为概念或保持延期；
- 模型返回的所有短 ID 必须可逆映射到数据库跨度，未知 ID 数为零；
- 扫描建议不得自动写入锁定译名。

## 10. 错误处理

结构校验失败时最多重试两次。第二次仍失败，则整批候选保持 `deferred_model_failure`，不部分提交概念。模型预算、上下文预算、磁盘预算或外部 API 限制超出时返回人工处理，不改变内部裁决逻辑。

数据库提交以裁决批次为事务边界。候选证据可以先写入，概念提升、工作译名和验证任务必须原子提交。崩溃恢复不得重复创建候选或概念。

## 11. 测试与验收

自动测试覆盖：跨度网格、普通词作为专名中心、并列整体和原子候选、所有格和复数归一化、短 ID 随机重排、未知 ID 拒绝、拆分和替代合法性、双重裁决冲突延期、工作译名冻结、依赖失效、事务化扫描重置、容量预算和审计归档定位。

生产逻辑不含 `Drotte`、`Corpse` 或 `Night` 的词汇特例；这些词只作为真实回归样本。小样通过标准是结构错误不进入工作词库，而不是要求 Flash 对所有文学性类型作出唯一解释。
