# FolioLoom EPUB 注释与链接保真规格

日期：2026-07-30
目标版本：v1.5.2
状态：已实现并通过本地端到端验收

## 1. 目标

以用户导入的原 EPUB 为导出模板，在翻译后保留：

- OPF、spine、nav、样式、图片、字体及其他非正文资源；
- XHTML 中原有的 `id`、`href`、`epub:type` 和元素层级；
- 脚注/尾注的正文跳转与返回链接；
- 跨章节片段链接；
- 外部 URL 的原始值。

正文、链接标签和注释正文可以翻译。系统不得靠字符偏移、模糊匹配或事后猜测恢复链接位置。

## 2. 核心契约

### 2.1 导入

EPUB 导入器继续按 OPF spine 顺序生成 canonical source。含行内元素的可翻译块使用稳定的、与文档和槽位序号绑定的结构槽标记。标记只描述槽位身份，不暴露或改写 `href`、`id`。

普通纯文本块不增加标记。结构块的所有可见文本都位于成对标记内；固定换行等不可翻译节点也拥有固定槽位。

### 2.2 翻译

模型必须：

1. 原样保留每个结构槽的开始、结束标记；
2. 保留槽位数量和顺序；
3. 只翻译槽位内部文本；
4. 不在结构块的槽位外新增正文。

本地校验器对上述契约 fail closed。缺失、重复、乱序、改写标记的结果不得提交。

### 2.3 导出

对于 EPUB 来源：

1. 重新校验 source ledger 的原始文件哈希；
2. 克隆原 EPUB 的全部成员；
3. 纯文本块只替换原文本节点；
4. 结构块按稳定槽位替换文本节点；
5. 原始标签、属性、资源路径和链接值保持不变；
6. 写入 lineage sidecar；
7. 对内部链接、片段目标和结构不变量做审计；
8. 仅在全部校验通过后原子发布输出文件。

旧项目若不是由支持结构槽的 EPUB 提取器导入，不进行猜测式恢复，继续使用既有重排导出。

## 3. Fail-closed 条件

- 原 EPUB 或 canonical source 哈希不匹配；
- source/target 段落数不匹配；
- 结构槽缺失、重复、乱序或槽外出现正文；
- 原始 XHTML 结构无法稳定定位；
- 输出新增悬空内部链接或丢失片段目标；
- 输出的链接边集合、`id` 集合或外部 URL 与原文件不同；
- ZIP 成员路径非法、重复或使用不支持的压缩方式。

失败时不得留下最终 EPUB；桌面导出仍在临时目录中回滚。

## 4. 验收

最小本地 EPUB 必须覆盖：

- 正文 `noteref` → 脚注；
- 脚注 → 正文返回链接；
- 跨章节链接；
- 外部 HTTPS 链接；
- 链接前后均有可翻译文字；
- 压缩和未压缩 ZIP 成员。

验收要求：

1. 导入后结构槽身份稳定；
2. 用确定性翻译替身完成全书翻译；
3. 导出 EPUB 可重新解析；
4. 链接标签和脚注正文已翻译；
5. `href`、`id`、`epub:type`、OPF/spine/nav/资源集合不变；
6. 所有内部链接解析成功；
7. 故意破坏一个槽位或链接时导出失败且不发布文件；
8. 核心测试、桌面测试、typecheck 和 build 门禁通过。

## 5. 非目标

- 不访问外部 URL 检查可达性；
- 不翻译图片内文字；
- 不支持 DRM、加密、签名、media overlay、CFI、SVG/MathML 内嵌链接的自动重写；
- 不为旧的整段译文做模糊对齐。
