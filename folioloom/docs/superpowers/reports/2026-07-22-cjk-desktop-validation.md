# FolioLoom 桌面端与日韩长篇翻译终验报告

日期：2026-07-22
分支：`feat/folioloom-desktop`

## 结论

本轮目标已经达到：DeepSeek V4 Flash 在 `high` 思考强度下的连接测试不再误报；桌面端模型配置、原稿导入、试译状态和打包路径通过回归；日语与韩语具备独立的语言识别、编码协商、章节结构、token 预算、残留检查与快速批量策略。真实 API 试跑覆盖完整日文测试书和约 20 万字符韩文样本。

## DeepSeek 连接测试

旧探针把模型最大输出固定为 32 token。开启 `high` 后，推理内容先耗尽预算，工具调用被 `finish_reason=length` 截断，界面因而把“输出不足”误判为“不支持结构化工具调用”。

修复后，探针复用正式运行时的 wire policy，并仅对合法的输出截断执行一次有界扩容重试。2026-07-22 的真实 `deepseek-v4-flash` / `high` 复测耗时 4.62 秒，以下五项全部通过：

- 流式输出；
- 结构化工具调用；
- 工具结果往返；
- reasoning 连续性；
- reasoning effort。

## 桌面端修复

- 连接测试开始后立即显示状态；成功和失败均提供明确结果。
- 测试失败时保留当前输入框中的 API Key，但不把失败密钥持久化。
- 探针结果绑定服务商和模型，切换服务商或模型后不会显示旧结果。
- 异步刷新使用 generation 隔离，旧项目和旧试译结果不能覆盖当前页面。
- EPUB、DOCX 和纯文本导入不再向读者暴露内部容器术语或项目路径。
- 同名但内容不同的书稿独立建项；旧的 `und` 韩文项目不会被错误复用。
- Electron IPC、导航、凭据和错误信息都通过边界校验及脱敏测试。

## 日韩支持

- 增加 `ja`、`ko` 独立语言画像，以及日语和韩语的句界、章节标题和文本密度配置。
- 韩语支持常见网文章节形式，例如 `제12화`、`12회` 及装饰性标题。
- 严格处理 UTF BOM、UTF-8、UTF-16、Shift-JIS、EUC-JP、EUC-KR 与 Windows-949；无法可靠区分时要求确认，不静默猜码。
- 解码后检查替换字符、孤立代理项、非法 Unicode、私用区填充、不可见控制符和常见乱码特征。
- 日语和韩语按实测字符/token 密度预算，避免沿用“4 字符约等于 1 token”的英语经验。
- 快速模式首译采用低成本 effort 和自适应并发；只对失败或高风险窗口做局部升级。
- 模型可见原文、预算估算和修复请求使用同一语义投影，避免布局标记造成预算与实际请求不一致。
- 每块保持段落一一对应，并检查异常缩短、膨胀、跨块重复、源语言残留及未闭合引号。

## 术语与实体安全

快速模式增加严格的 nonce 分帧词汇协议；若服务商忽略帧但只返回单一合法 JSON 数组，也可安全接收。所有候选都必须通过来源白名单、类别、置信度和重复检查：

- 用户锁定词始终优先；
- 原文明确出现的汉字写法优先；
- 仅凭韩文或假名推断的专名只作为软偏好，不硬锁定；
- 被模型原样复制为韩文或假名的“译名”被丢弃；
- 未决项不进入成功缓存；
- 低置信度实体连接保持 provisional，不覆盖已确认术语。

真实韩文定向复测中，`묵향`、`용천익`、`혁무상` 在跨块出现时分别稳定为“墨香”“龙天益”“赫武相”。其中没有原文汉字证据的音译仍保持可修订软锚点。

## 剩余边界

- 只给出韩文或假名而没有汉字证据的人名，不可能由工程系统确定唯一汉字写法；系统选择“保持一致但不锁死”，后续发现证据可自动修订。
- Flash 版适合工程回归和可读试译，不代表出版级文学润色质量；正式模型升级后仍需重新做质量盲评。
- 低置信度别名目前安全地保持 provisional。独立的全书别名再验证属于后续 P2 增强，不是当前正确性阻断。
