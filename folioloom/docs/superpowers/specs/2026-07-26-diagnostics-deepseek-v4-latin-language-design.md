# FolioLoom 诊断导出、DeepSeek V4 与拉丁语种验证设计

日期：2026-07-26  
目标版本：1.4.0  
状态：已发布

## 1. 背景与目标

桌面端用户目前可能只看到“试译失败”或一段被压缩的技术详情。失败发生在书稿导入、模型连接、结构化协议、试译翻译、确定性校验、修复或 SQLite 提交中的哪一层，维护者无法仅凭截图可靠判断。应用进程重启后，短暂的界面错误也可能丢失。

本版本完成三项相关工作：

1. 建立不含原文、译文和密钥的本地诊断事件流，并允许用户一键导出单个 JSON 诊断包；
2. DeepSeek 入口只提供当前有效的 `deepseek-v4-flash` 和 `deepseek-v4-pro`，清除旧模型名造成的隐性失败；
3. 用真实德语小说试译暴露并修复拉丁语种画像中的结构和候选噪声问题，同时补齐德语、法语和西班牙语回归。

诊断功能的首要原则是可定位问题，其次才是信息丰富。任何可能泄露用户书稿或凭据的字段都不进入日志。

## 2. 已取得的德语基线证据

测试文本采用 Project Gutenberg 的德文《变形记》，仅作为本地、未跟踪的验证材料。

- 原文：141,034 Unicode scalar；
- 自动语言检测：`de`，置信度 `0.98`；
- 无损检查：原文覆盖 141,034 / 141,034，29 个窗口，没有完整性事件；
- 首个窗口：4,870 字符，估算 1,370 token；
- DeepSeek V4 Flash，`high`：65.9 秒完成，5 次模型调用；
- 结果：`completed_with_warnings`，没有失败窗口或人工处理窗口；
- 人名 `Gregor Samsa` 稳定译为“格里高尔·萨姆沙”，正文通顺，段落覆盖完整。

基线同时暴露出两个真实问题：

1. `I.` 这类德文小说常见章节标题没有被结构画像识别，检查结果中 `annotationCount=0`，窗口的 `chapterTitle` 全为空；
2. 德语普通名词首字母大写，现有拉丁语候选器把 `Augen`、`Bett`、`Eltern`、`Fenster`、`Kopf`、`Rücken`、`Tisch`、`Zimmer` 等普通名词送入锚点裁决。模型最终把它们判成 `ordinary_word/contextual`，因此译文没有被错误锁死，但产生了知识噪声和不必要的上下文开销。

由此可得：当前德语翻译主链可以工作，质量也没有立即失控；但不能称为已经充分适配。需要修复结构识别和德语名词候选策略后再发布“正式支持”。

## 3. 方案选择

### 3.1 采用方案

采用“持久化脱敏事件 + 单文件诊断包”：

- Electron 主进程持续记录结构化 JSONL 事件；
- 错误面板和全局入口都可以导出诊断；
- 导出时把环境摘要、当前状态和最近事件合并成一个 UTF-8 JSON 文件；
- 导出文件可以直接发送给维护者，不要求用户安装解压工具或理解日志目录。

### 3.2 不采用的方案

- 仅复制当前错误：进程重启或界面复位后没有历史，无法定位跨层失败；
- 打包原始数据库、原文片段和模型响应：虽然信息更多，但有书稿、译文、私人路径和密钥泄露风险；
- 记录所有 IPC 请求参数：其中可能直接包含 API Key、源文件路径或知识导入内容，不符合隐私边界。

## 4. 诊断架构

### 4.1 主进程事件记录器

新增单一职责的 `DesktopDiagnosticLogger`。日志目录位于 Electron `userData/diagnostics`，按 JSONL 写入，采用有界轮转：

- 单文件最大 2 MiB；
- 最多保留 4 个文件；
- 超限后先轮转再写入；
- 每个事件最大 16 KiB；
- 写入失败不得影响翻译主流程。

事件公共字段：

- `schemaVersion`
- `timestamp`
- `severity`
- `event`
- `operationId`
- `channel`
- `phase`
- `durationMs`
- `outcome`
- `errorCode`

允许的业务元数据：

- 应用版本、Electron/Node/Chrome 版本、操作系统版本与架构；
- provider ID、模型 ID、reasoning effort；
- 书稿格式、识别语言、编码名称、字符数、哈希前缀；
- run/window 的不透明 ID、状态、尝试次数、调用数和 token 预算；
- 探测状态、协议能力、校验错误代码和恢复结果。

禁止记录：

- API Key、Authorization 头、cookie；
- 原文、译文、模型 prompt、模型原始响应；
- 用户知识内容、术语译文、注释正文；
- 完整源文件路径、完整自定义接口 URL；
- SQLite 文件本体。

### 4.2 捕获边界

IPC 包装器只记录通道、耗时和结果，不记录请求 payload。以下服务增加安全事件：

- 书稿选择、解析、导入与结构检测；
- 模型列表获取、能力探测和配置保存；
- 试译的 preparing、translating、checking、committing、completed、failed；
- 整本开始、暂停、恢复、窗口失败和运行完成；
- 导出预检、审计和文件发布；
- 主进程未捕获异常及未处理 Promise 拒绝。

所有捕获点共享 `operationId`。试译事件额外关联 `runId` 和 `windowId`，这样维护者可以从“按钮点击”追踪到具体失败窗口，但日志中不会出现正文。

### 4.3 错误序列化与脱敏

现有 `toDesktopError()` 继续为界面返回简短中文错误，但诊断记录保存经过脱敏的：

- 错误类名；
- 业务错误码；
- 阶段；
- 最多 5 层 `cause` 链；
- 有界 message；
- 有界 stack。

脱敏器在写入时和导出时各运行一次，形成双层防护。它应覆盖：

- Bearer/API Key/token 常见格式；
- URL query 中的 key/token；
- JSON 字符串中的认证字段；
- Windows 用户目录、项目目录和临时目录；
- 自定义 Base URL 的 path、query 和 fragment。

路径替换为 `<userData>`、`<project>`、`<temp>` 或 `<app>`。自定义服务只记录 `customProvider=true` 和不可逆 host 哈希。

### 4.4 诊断包

导出为 `FolioLoom-diagnostics-YYYYMMDD-HHmmss.json`，结构包含：

- `manifest`：schema、生成时间、应用版本；
- `environment`：安全的系统版本摘要；
- `model`：当前 provider、模型、effort、最近探测结果；
- `source`：格式、语言、编码、字符数、哈希前缀；
- `operation`：最近失败操作及阶段；
- `runSummary`：仅状态、计数、预算和脱敏错误码；
- `events`：按时间排序的最近有界事件；
- `privacy`：明确列出已排除的数据类别。

导出前对最终对象执行递归敏感字段扫描。扫描未通过时拒绝发布文件并给出本地错误，不生成“可能已经脱敏”的半成品。

### 4.5 GUI

增加两个入口：

1. 错误面板中的“复制诊断摘要”和“导出诊断包”；
2. 左侧底部始终可用的“导出诊断”，用于界面已经复位或重启后的情况。

成功后显示实际保存位置；取消保存不显示失败。按钮调用主进程保存对话框，renderer 不接收日志目录或任意文件路径。

## 5. DeepSeek V4 策略

DeepSeek 预设改为固定模型清单：

- `deepseek-v4-flash`
- `deepseek-v4-pro`

具体行为：

- `modelDiscovery` 使用 curated 模式；
- DeepSeek 禁止手工输入任意模型 ID；
- 新用户默认选中 `deepseek-v4-flash`，也可以改选 Pro；
- 保存的 `deepseek-chat`、`deepseek-reasoner` 配置不静默运行；
- 读取到旧配置时清除旧 probe，界面回到 V4 Flash，并要求重新测试连接；
- 错误说明使用 `DEEPSEEK_MODEL_RETIRED`，明确提示旧模型名已停用；
- CLI 配置校验同样拒绝两个旧模型名，避免桌面端和命令行行为分裂；
- 文档、测试夹具和 Release 说明不再把旧模型名作为正常示例。

接口地址继续使用官方 OpenAI-compatible `/v1` 入口。本次只调整模型标识和用户选择，不改成其他私有协议。

## 6. 德语、法语和西班牙语支持

### 6.1 语言检测

保留离线、确定性的自动检测，但增加三类回归：

- 正常小说正文；
- 带英文版权页或混合前言的正文；
- 短文本或低置信文本。

高置信时自动采用检测结果；低置信时维持 `und`，并在 GUI 显示可选的原文语言覆盖，不伪造检测结果。覆盖值进入 source ledger，后续恢复必须保持一致。

### 6.2 章节结构

扩充并测试常见标题：

- 德语：`KAPITEL 1`、`1. Kapitel`、`Erstes Kapitel`、独立的 `I.`；
- 法语：`CHAPITRE I`、`PREMIER CHAPITRE`、独立罗马数字；
- 西班牙语：`CAPÍTULO I`、`CAPITULO 1`、独立罗马数字。

独立数字和罗马数字仍需结构注释器的空行、位置和独占行证据，不能仅靠正则把正文中的数字误判为章节。

### 6.3 德语普通名词噪声

不维护一份硬编码德语名词表。候选器改为依据证据区分：

- 明确命名或别名线索；
- 多位置共现和上下文角色；
- 大小写形态；
- 是否只表现为普通词义；
- 已有 `ordinary_word` 负证据。

模型裁决为 `ordinary_word` 的候选进入轻量负缓存，而不是活动术语知识；后续窗口不再重复提交，也不投影进翻译上下文。只有 `proper_name`、`unique_title`、术语或有关系证据的形式才形成可持续锚点。

这个规则以语义类别为准，对其他“普通名词也经常大写”的语言同样适用，不绑定《变形记》中的具体词汇。

### 6.4 验证

离线测试至少覆盖：

- `de/fr/es` 自动检测和低置信回退；
- UTF-8、UTF-16 及 Windows 常见编码导入；
- 章节标题、句子边界、重音字符和弯引号；
- 术语候选、普通名词负缓存和别名线索；
- 中文译文中的源语言残留；
- 结构完整性和严格段落对齐。

真实门禁：

- 用当前德文《变形记》样本重跑一个 4–6k 字符窗口；
- 必须完整提交、无乱码、无异常源语言残留；
- 普通德语名词不得进入活动全局锚点；
- 章节 `I.` 必须产生结构注释；
- 记录耗时、调用数、状态和警告，但不把正文提交到仓库。

发布候选实测结果（2026-07-26）：

- 当前导入器自动识别为 `de`，置信度 `0.98`，141,034 / 141,034 Unicode scalar 完整覆盖；
- `I.`、`II.`、`III.` 均形成章节注释；
- DeepSeek `deepseek-v4-flash`、`high` 完成一个 4,984 字符德语正文窗口，耗时 48.3 秒，3 次模型调用；
- 原文与译文均为 7 个段落，译文没有替换字符或异常德语散文残留，没有失败或人工处理窗口；
- 20 个 `ordinary_word` 裁决全部持久化为 `contextual` 负缓存，活动普通词锚点为 0。

法语和西班牙语本轮使用离线完整链路回归；在没有同等真实模型样本前，Release 说明写“已支持并补齐工程回归”，不宣称经过出版级质量评测。

## 7. 测试与验收

实施遵循 TDD。必须先增加失败测试，再编写生产代码。

验收门槛：

1. 日志轮转、异常链、双重脱敏和最终敏感字段扫描测试通过；
2. 任意 IPC payload 中放入模拟 API Key、原文和私人路径，导出文件中均不可出现；
3. 试译在模型探测、协议、翻译、校验、修复、提交各阶段失败时，诊断包能指出对应阶段；
4. DeepSeek GUI 只显示 V4 Flash/Pro，旧配置不会被调用；
5. 德语真实试译门禁通过，德法西离线回归通过；
6. `npm test`、desktop tests、typecheck、desktop build 全部通过；
7. 从打包后的 Windows 目录便携版手工跑通：选择书稿、连接模型、试译失败模拟、导出诊断、正常试译和导出结果；
8. 版本号统一更新为 1.4.0，生成目录便携 ZIP 与现有发布格式；
9. Git 工作区干净，Release 资产可以由普通用户下载。

## 8. 发布说明重点

- 增加隐私安全的一键诊断导出，便于远程定位试译失败；
- DeepSeek 仅保留 V4 Flash 和 V4 Pro，旧模型名不再误入运行；
- 德语真实试译已通过，并修复章节标题和名词大写造成的候选噪声；
- 法语、西班牙语补齐工程回归；
- 诊断包不包含 API Key、原文、译文或完整私人路径。
